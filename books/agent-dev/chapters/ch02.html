第 2 章 Agent 简史——从 ELIZA 到多 Agent 浪潮

60 年，3 次"Agent 热"，2 次寒冬。每一个今天让你眼前一亮的概念，几乎都能在历史里找到原型。理解历史不是为了怀旧，而是为了少踩坑——以及看清楚这一次到底是不是真的不一样。

2.1 引子：为什么要回头看 60 年

很多人问："Agent 不就是 2023 年才火起来的吗？为什么还要讲 1966 年的 ELIZA？"

三个理由。

第一，避免重复发明。 1990 年代"智能体"火过一次、烧光了钱、退了潮；2023 年又火了一次、退了半次潮、2024 年再起来。如果你不知道 1990 年代那批人踩过什么坑（"自主 Agent 完全跑不通任务"），你会高高兴兴地把同一个坑再踩一遍。

第二，理解概念漂移。 "Agent"这个英文词在 60 年里的意思变了至少 5 次——从"能动的实体"到"软件机器人"到"自主决策系统"再到今天的"LLM 驱动的多步任务执行者"。它从来不是一个技术概念，而是一个愿景概念。理解这个漂移，比记住任何一条技术细节都重要。

第三，建立时间感。 AI 行业有一个很糟糕的习惯——把"过去 3 年"叫做"传统"、把"过去 1 年"叫做"历史"。但 60 年的尺度会告诉你：2024 年 Claude Computer Use 那种"AI 操作计算机"的想法，1969 年 Shakey the Robot 就已经做过了（虽然弱一万倍）。

这一章我们就用 60 年时间线、3 次浪潮、几十个关键人物，把"Agent 是怎么走到今天的"这件事讲清楚。

2.2 1960s 起源：早期智能体的两个里程碑

任何关于 Agent 历史的书，都绕不开两个名字：ELIZA 和 Shakey the Robot。

2.2.1 ELIZA（1966）——"假装听懂你说话的程序"

1966 年，MIT 的 Joseph Weizenbaum 写了一个程序，叫 ELIZA。它的角色是一个罗杰斯心理治疗师（Rogerian psychotherapist）——一种以"重复对方的话、引导对方自我倾诉"为核心技术的心理流派。

ELIZA 的工作方式简单到让人吃惊：模式匹配 + 替换。下面是一个示意版本（不完整，原始版本更精巧）：

import re
import random

# 模式：正则 -> 替换模板（占位符 0 表示捕获组）
RULES = [
    (r"我需要(.*)",
     ["你为什么需要{0}？",
      "真的需要{0}吗？"]),
    (r"我(.*)你",
     ["你{0}我这件事，能再具体说说吗？",
      "你{0}我，是因为什么？"]),
    (r"(.*)妈妈(.*)",
     ["说说你的妈妈。",
      "你和你妈妈的关系是怎样的？"]),
    (r"你好",
     ["你好，请随便说。"]),
    (r"(.*)",
     ["能再多说一点吗？",
      "你为什么会这样说？",
      "有意思，请继续。"])
]

def eliza_reply(user_text: str) -> str:
    for pattern, responses in RULES:
        m = re.search(pattern, user_text)
        if m:
            template = random.choice(responses)
            return template.format(*m.groups())
    return random.choice(["嗯。", "我听到了。", "继续。"])

if __name__ == "__main__":
    print("ELIZA: 你好，我是 ELIZA，请随便说。")
    while True:
        u = input("你: ").strip()
        if u in ("quit", "exit", "再见"):
            print("ELIZA: 再见。")
            break
        print(f"ELIZA: {eliza_reply(u)}")

我们和它聊几句：

你: 我最近很焦虑
ELIZA: 能再多说一点吗？
你: 我觉得我妈妈不理解我
ELIZA: 说说你和你妈妈的关系。
你: 我需要被理解
ELIZA: 你为什么需要被理解？

它什么都没听懂。 它只是按照预设的规则把"我需要 X"重新组装成"你为什么需要 X"。但 Weizenbaum 的秘书在使用 ELIZA 一段时间后，请求他离开房间——她真的开始向 ELIZA 倾诉了。

这个故事后来成了 AI 史上最著名的现象之一，被叫做 ELIZA effect：人类会把自己对"理解"的直觉投射到一个根本不理解的系统上。2025 年我们和 LLM 聊天时，这个 effect 一点都没消失。

重要区分：ELIZA 是不是 Agent？这个看定义。Anthropic 2024 年的标准是"LLM 动态决定自己的处理流程"——ELIZA 没有 LLM，也没有动态决策，它更接近一个 chatbot。但在 1960 年代，它已经是当时最像"对话 Agent"的东西了。

2.2.2 Shakey the Robot（1969）——第一台"会规划"的机器人

如果 ELIZA 是"对话 Agent 的祖先"，那 Shakey the Robot 就是"具身 Agent 的祖先"。

1966 年到 1972 年间，SRI International（斯坦福研究所）的 Charles Rosen 领导的小组造了一台叫 Shakey 的机器人——之所以叫 Shakey，是因为它移动起来颤颤巍巍，像要散架。Shakey 在一个为它专门布置的房间里移动，房间里有斜坡、箱子、开关，它要完成"把箱子推到斜坡上再关灯"这种多步任务。

听起来很弱是吧？但它做对了一件 60 年代其他机器人没做过的事：它会规划。

它的软件栈是这样的：

  1. 感知层：摄像机和测距仪，把场景转换成几何图
  2. 世界模型：用 STRIPS（Stanford Research Institute Problem Solver）规划器，把世界状态抽象成"在房间 R，灯 L 是开着的，箱子 B 在位置 P"这种逻辑事实
  3. 规划层：STRIPS 在事实集合上做"前向搜索"——找一条从"初始事实"到"目标事实"的逻辑动作序列
  4. 执行层：把每个逻辑动作翻译成电机指令

这一步规划能力，是 60 年代"Agent"和"机械臂"的分水岭。 之前，机器人是写死的；之后，机器人开始"自己想办法"。

1960 年代末，Marvin Minsky（MIT，他在 1961 年的论文 Steps Toward Artificial Intelligence 中已隐含"智能体"概念）在多个公开场合把 Shakey 称为"第一个具备某种自主性的电子人物理 Agent"。

2.3 1980s-1990s：智能体理论的"黄金十年"

1970 年代是 AI 寒冬，1980 年代开始复苏。这一轮的复苏里，"Agent"成了一个正经的学术术语，理论框架被搭起来。

2.3.1 Minsky《Society of Mind》（1986）

1986 年，MIT 的 Marvin Minsky 出版了《Society of Mind》（《心智社会》）。这本书的核心观点大胆到当时很多人无法接受：

智能不是来自某个单一的、庞大的"我"，而是来自大量简单 Agent 的协作。 就像人类社会里"政府"不是一个具体的人，而是无数个体决策涌现出来的一样，智能是许多"小 Agent"互相作用的结果。

这本书影响了两代人——它直接催生了 1990 年代的 multi-agent system（MAS）研究，也为 2025 年我们看到的"多 Agent 框架"埋下了种子。

2.3.2 Pattie Maes 与"自主 Agent"（1990-1995）

MIT Media Lab 的 Pattie Maes 在 1990 到 1995 年间，发起了一波叫"autonomous agents"的研究运动。她的核心思想：

Agent 不应该等用户命令；它应该观察用户的行为，主动提供帮助。

Maes 团队做了几个 demo 系统，最有名的是 Letizia（一个会主动帮你浏览网页的浏览器助手）和 Firefly（一个会主动推荐朋友的社交系统）。这些系统在 1990 年代的学术会议上惊艳了所有人——它们看起来"主动、有目标、会自己想办法"。

但问题是：它们跑得很差。在 1995 年的 CHI 大会上，Maes 自己承认：让 Agent "自主"到用户满意的程度，难度被严重低估了。这波热潮从 1995 年开始迅速冷却。

2.3.3 Rodney Brooks 与"包容架构"（1986-1991）

MIT AI Lab 的 Rodney Brooks 提出了一个反主流的 Agent 架构——subsumption architecture（包容架构）。他的观点：

不要从"思考"开始，要从"行动"开始。 不要做"先感知→规划→决策→执行"的传统机器人，要做"我有一堆简单的反射层，下层压住上层"的行为机器人。

Brooks 的代表性机器人叫 Allen 和 Genghis（六足行走机器人，1990）。它们不"思考"，它们只是"动"——遇到障碍左转、感应到光源直行、上层命令覆盖下层。没有世界模型，没有规划，没有"智能"——但它们能走能避障。

1991 年 Brooks 发表的论文 Intelligence Without Reason（没有推理的智能）成了行为机器人学（behavior-based robotics）的圣经。他的核心论点：

智能是行为的表现，不是推理的结果。 你不需要"思考"才能"智能"。

这个观点 30 年后被 Yann LeCun 用在 2022 年的 JEPA（Joint Embedding Predictive Architecture）里复活，成了 2024-2025 年"世界模型"风潮的源头之一。

2.3.4 1990s 末的多 Agent 系统

到 1990 年代末期，多 Agent 系统（MAS）成了一个独立的子领域：

  • 合同网协议（Contract Net Protocol, 1980 by Smith & Davis）—— Agent 之间通过"招标-投标"分配任务
  • BDI 架构（Belief-Desire-Intention, 1987 by Rao & Georgeff）—— Agent 的内部状态分三层
  • FIPA 规范（1996, Foundation for Intelligent Physical Agents）—— Agent 通信语言的早期标准

这些理论在 2000 年代被工业界彻底抛弃了——它们太学术、太复杂、太难落地。但它们为 2024-2025 年的多 Agent 框架（CrewAI、AutoGen）留下了完整的术语表。

2.4 2000s-2010s：寒冬与"命令式助手"

进入 2000 年，AI 行业的情绪和 2023-2024 年比，像两个完全不同的星球。

2.4.1 寒冬与"AI 冬天"周期

AI 行业经历过好几次"冬天"：

  • 第一次寒冬（1974-1980）：Lighthill 报告 + DARPA 削减资助
  • 第二次寒冬（1987-1993）：LISP 机市场崩盘 + 专家系统失败
  • 第三次寒冬（2010 年代后期）：深度学习承诺过多、兑现不足

每一次冬天过后，AI 行业都会学乖一点——不再喊"我们要造通用智能"这种话，转去做一些能落地、有收入的事情。

2000-2010 年代就是"学乖"的时代。Agent 这个词在工业界基本消失了——大家更愿意用"virtual assistant"（虚拟助手）、"chatbot"（聊天机器人）这些听起来更保守的词。

2.4.2 Siri（2011）——"智能助手"这个词被注册

2011 年 10 月，Apple 推出 Siri——一个能听、能说、能帮你"打电话、发短信、设闹钟" 的语音助手。Siri 来自 SRI International（对，就是 1969 年做 Shakey 的那个研究所）的 2000 年代项目，2010 年 Apple 收购了它，2011 年集成进 iPhone 4S。

Siri 是第一个让"和机器对话"这件事进入大众视野的产品。在 Siri 之前，语音助手是军用、客服、电话 IVR；Siri 之后，"和手机说话"成了一种日常行为。

但 Siri 不是 Agent——它是命令式助手。你说"打电话给妈妈"，它执行；你说"我应该给谁打电话"，它一头雾水。

2.4.3 Alexa（2014）与 Google Assistant（2016）

  • Amazon Echo / Alexa（2014 年 11 月发布）——把"智能助手"搬进了一个圆柱形音箱
  • Google Assistant（2016 年 5 月发布）——Google 在 Allo 和 Pixel 上推出的统一助手
  • Microsoft Cortana（2014-2023）——Windows 10 内置，2023 年停止支持
  • Samsung Bixby（2017）——Galaxy 手机内置

这一波"智能助手"的共同特征：

特征1990s 智能体2010s 智能助手
自主性高（理论）低（命令式）
触发方式主动观察被动命令
任务范围开放受限（"打电话、放音乐"）
技术栈学术（BDI、合同网）工业（语音识别 + 模板）
收入无有（硬件 + 数据）
商业可行性低中

Siri 和 Alexa 拯救了"Agent"这个词的商业信誉——它们让普通人接受了"我会和一个程序说话"这件事，为 2023 年的"LLM Agent"铺平了心理基础。

2.5 2016 转折点：AlphaGo 与"强化学习的胜利"

2016 年 3 月，DeepMind 的 AlphaGo 以 4:1 战胜韩国棋手李世石。这件事对 AI 行业的影响远不止围棋本身。

2.5.1 AlphaGo 的技术遗产

AlphaGo 的核心架构是双网络：

  1. 策略网络（Policy Network）：给定棋盘，预测下一步落子概率分布
  2. 价值网络（Value Network）：给定棋盘，预测胜率

加上 蒙特卡洛树搜索（MCTS） 做规划，AlphaGo 成了"深度神经网络 + 规划 + 强化学习"的第一个工业级胜利。

2.5.2 对 Agent 研究的启发

AlphaGo 给 Agent 研究者最重要的礼物不是技术，而是信心：

如果"搜索 + 学习"组合能在围棋上击败人类世界冠军，它也能在现实任务上击败人类。

2017 年 DeepMind 推出 AlphaZero（去掉人类棋谱、纯自我对弈），进一步把"通用 Agent"的可能性推到台前。2018 年的 AlphaStar（星际争霸 II）和 2019 年的 AlphaFold 2（蛋白质结构预测）都延续了这个范式。

这一波虽然没直接产生"Agent"产品，但奠定了 2020 年代 Agent 框架的算法底座——LLM Agent 用的"规划 + 调用工具"模式，本质上是 AlphaGo "策略网络 + MCTS" 的语言版本。

2.6 2022 黎明：ChatGPT 引发 LLM 浪潮

2022 年 11 月 30 日，OpenAI 发布 ChatGPT。这是 60 年 Agent 史的第二个真正分水岭（第一个是 1969 年 Shakey）。

2.6.1 ChatGPT 改变了什么

ChatGPT 的真正创新不是 GPT-3.5 模型本身（GPT-3 2020 年就有了），而是RLHF + 对话界面：

  1. RLHF（Reinforcement Learning from Human Feedback）：用人类偏好训练一个 reward model，再用 PPO 优化 LLM
  2. 对话界面：把 LLM 包装成一个可以聊天的窗口，隐藏了所有"提示工程"的复杂性

2.6.2 三个连锁反应

连锁反应 1：推理即接口。 ChatGPT 让所有人意识到——LLM 是一种"通用推理引擎"。你不需要为每个任务训练一个模型，你只需要问它。

连锁反应 2：涌现能力。 2022 年底到 2023 年初，研究者发现 GPT-3.5/4 在没专门训练过的情况下，能做数学题、能写代码、能理解笑话。"涌现"这个词重新成为热门。

连锁反应 3：Agent 的可能性。 如果 LLM 真的能"推理"，那让 LLM "调用工具" "做规划" "持续执行任务"就成了自然而然的下一步。这正是 2023 年 AutoGPT 的灵感来源。

2.7 2023 第一次"Agent 狂热"

2023 年 3 月，Significant Gravitas 的 Toran Bruce Richards 发布了 AutoGPT。它的 GitHub repo 在 4 月冲上 10 万 star，是有史以来 star 增长最快的开源项目之一。

2.7.1 AutoGPT 做了什么

AutoGPT 的核心 idea 简单到粗暴：

给 GPT-4 一个目标， 让它自己拆解任务、自己调用工具、自己循环执行，直到完成。

具体的循环是：

  1. 接受用户输入的目标
  2. 让 LLM 思考"下一步该做什么"
  3. 调用工具（搜索、文件操作、shell 命令……）
  4. 把工具结果喂回 LLM
  5. 回到第 2 步，直到 LLM 说"任务完成"

2.7.2 BabyAGI（2023 年 4 月）

紧随 AutoGPT 之后，Yohei Nakajima（一个独立开发者，Hacker News 用户）发布 BabyAGI。BabyAGI 简化了 AutoGPT 的代码，加了一个任务列表——LLM 每完成一步就更新这个列表，让 Agent 不会"忘了自己在干嘛"。

AutoGPT 和 BabyAGI 的 GitHub 仓库在 2023 年 Q2 一起统治了 Hacker News 首页。

2.7.3 第一次"过热"与第一次"失望"

2023 年 4-6 月，AutoGPT 类的项目"什么都能做"的故事在 Twitter 疯传。但当人们真的把它跑起来时，遇到了三个问题：

  1. 循环死锁：LLM 经常陷入"我想干 X → 干 X → 我想干 X" 的循环
  2. 上下文爆炸：每一步的思考都塞进 context，几步之后超过上下文窗口 或 成本爆炸
  3. 工具调用不稳定：早期 GPT-4 的 function calling 经常生成格式错误的 JSON

到 2023 年 7-8 月，AutoGPT 的热度骤降，第一次"Agent 狂热" 退潮。这段经历被许多早期开发者总结为："AutoGPT 是一个伟大的 demo，但不是一个产品"。

2.7.4 评测的诞生

狂热退潮后，社区做了一件更有价值的事——建评测：

  • AgentBench（2023 年 7 月，清华 & 复旦大学）—— 8 个环境测 Agent 综合能力
  • SWE-bench（2023 年 10 月，Princeton）—— 让 Agent 修 GitHub 真实 issue
  • GAIA（2023 年 11 月，Meta AI & HuggingFace）—— 多模态 Agent 评测
  • HotpotQA / WebShop—— 经典 Agent 任务基线

评测让"Agent 能力"从"谁的故事好听" 变成了"谁跑分高"——这为 2024 年的冷静发展打下了基础。

2.8 2024 落地年：Computer Use + 框架爆发

2024 年是"Agent 从 demo 走向产品"的转折年。三件事值得记入史册。

2.8.1 Anthropic Computer Use（2024 年 10 月）

2024 年 10 月 22 日，Anthropic 发布 Claude 3.5 Sonnet (new)，其中最引人注目的能力是 Computer Use——让 Claude 像人一样操作计算机：

  • 看屏幕截图
  • 移动鼠标、点击、滚动
  • 打开应用、输入文字
  • 在不同窗口间切换

Computer Use 不是"在沙盒里跑命令"，它是"在真实的操作系统上代替你动手"。发布时的 demo 视频里，Claude 帮研究员订机票、填表格、查资料——而且中途会主动修正自己的错误。

Computer Use 重新定义了"具身 Agent"的可行性——第一次，你不必为 Agent 写专门的 API 集成，它能直接用人类用的软件。

2.8.2 OpenAI o1（2024 年 9 月）

2024 年 9 月 12 日，OpenAI 发布 o1——第一个"在回答前会内部思考" 的模型。o1 在 AIME、GPQA、Codeforces 等高难度基准上一举超过人类专家。

o1 对 Agent 的影响是深远的：

Agent 不再只是"调用 LLM 完成单步任务"；Agent 可以调用一个"会思考的 LLM" 完成复杂任务。 "内部思考" 把 context 的负担从用户侧转移到了模型侧。

o1 之后，reasoning model（推理模型）成了标配——Claude 3.7 Sonnet Extended Thinking（2025 年 2 月）、DeepSeek-R1（2025 年 1 月）、Gemini 2.0 Flash Thinking（2024 年 12 月）——整个行业进入了"思考 + 行动"的 Agent 时代。

2.8.3 MCP 协议（2024 年 11 月）

2024 年 11 月 25 日，Anthropic 发布了 Model Context Protocol (MCP)——一个标准化的工具调用协议。

MCP 解决了一个 2023 年就让人头疼的问题：每个 LLM 供应商都有自己的一套工具定义格式（OpenAI function calling、Anthropic tool use、Google function calling 都不一样）。结果就是同一个工具要写 3 份适配代码。

MCP 提出"一个工具 = 一个 MCP server"——只要你的工具暴露成 MCP server，任何支持 MCP 的 LLM 都能用。到 2025 年底，OpenAI、Google、Replit、Codeium 等先后宣布支持 MCP，它事实上成了 Agent 工具调用的 HTTP。

2.8.4 Devin（2024 年 3 月）

2024 年 3 月，Cognition Labs 推出 Devin——一个被宣传为"全球首位 AI 软件工程师" 的 Agent。Devin 能：

  • 读 GitHub issue
  • 自己 clone 仓库、改代码、跑测试
  • 在 Slack 里回答人类的问题
  • 提交 PR

Devin 发布时有一段 4 分钟的 demo 视频，整段视频里 Devin 端到端完成了一个真实的 GitHub issue——从读 issue 到改代码到开 PR，整个过程没人为干预。

Devin 后续被证明能力被宣传夸大——Devin 2024 年 3 月版本在 SWE-bench Verified 独立评测中通过率约 13%（与 Cognition 早期宣传的 87% 差距巨大）。但它开启了一整个赛道——"AI 工程师"作为产品 成了 2024-2025 年最热的创业方向之一。

2.9 2025 标准化年：多 Agent 协议 + 企业落地

2025 年是"Agent 协议化"和"企业落地"的双重元年。

2.9.1 OpenAI Operator（2025 年 1 月）

2025 年 1 月 23 日，OpenAI 推出 Operator——一个基于 GPT-4o / o1 的浏览器内 Agent。Operator 嵌在一个独立的浏览器窗口里，可以直接操作 Chrome。

Operator 与 Computer Use 的差异：

维度Computer Use (Anthropic)Operator (OpenAI)

模型Claude 3.5 SonnetGPT-4o / o1
速度较慢（截图思考）较快（DOM 操作）
适用场景系统级任务网页任务

2.9.2 A2A 协议（2025 年 4 月）

2025 年 4 月，Google 联合 50 多家公司（包括 Atlassian、Box、Cohere、Intuit、LangChain、MongoDB、Salesforce、SAP、ServiceNow 等）发布 Agent2Agent (A2A) Protocol——让不同厂商的 Agent 能互相通信。

A2A 提出的"Agent Card"概念类似 OpenAPI 规范——每个 Agent 公开一个 JSON 描述，别的 Agent 通过 A2A 协议发现并调用它。到 2025 年底，超过 100 家公司宣布支持 A2A。

A2A 与 MCP 互补：

  • MCP：Agent 使用 工具（tool use）
  • A2A：Agent 调用 Agent（agent-to-agent）

2.9.3 Google ADK（2025 年 4 月）

2025 年 4 月，Google 发布 Agent Development Kit (ADK)——一个开源 Python 框架，让开发者用 Google Gemini 构建多 Agent 系统。ADK 的核心抽象是"Agent as a Function"——Agent 像普通函数一样被组合。

2.9.4 CrewAI 与 LangGraph 成熟

到 2025 年 Q2，CrewAI 和 LangGraph 成了多 Agent 框架的事实标准：

  • CrewAI 强调"角色化"——给每个 Agent 设定 role、goal、backstory
  • LangGraph 强调"图状态"——把 Agent 工作流建模为有向图

两者代表了"多 Agent" 设计的两种哲学：CrewAI 是"虚拟团队"、LangGraph 是"工作流引擎"。

2.10 2026 Agentic AI 元年：复盘与展望

2026 年是本书写作的这一年。截至 2026 年 6 月，我们可以做一次冷静的复盘。

2.10.1 2026 年现状

企业落地：

  • 客服 Agent：超过 60% 的中大型企业部署了某种"AI 客服"（多数还是 LLM + 规则）
  • 研发 Agent：GitHub Copilot、Cursor、Cognition Devin 等被广泛使用
  • 数据分析 Agent：NL2SQL 工具在 2025 年后开始稳定落地
  • 销售 Agent：相对滞后，但 Outreach、Apollo 等开始集成

2.10.4 2026 年的判断

我们敢做几个经过事实检验的判断：

  1. 第三次浪潮是"真的"。证据是 OpenAI 在 2024 年营收增长超 3 倍、Anthropic 估值 2024 年 5 月达到 600 亿美元、2025 年 2 月再升至 1840 亿美元——这是真实资本在真实流向 Agent。
  2. 但 Agent 还没"通用化"。2026 年 6 月的 SOTA Agent 在 SWE-bench Verified 上大约 70% 通过率，离"取代软件工程师"还远。在长程任务（>1 小时）上的可靠性仍是个开放问题。
  3. 协议标准化是 2025 年最大的进步。MCP（工具）+ A2A（Agent 通信）让"组合" Agent 成为可能，这比单个 Agent 变强的影响更深远。
  4. "Skills 体系"是 2026 年的新趋势。Anthropic 在 2025 年 11 月推出的 Skills（让 Agent 学习"做事的方法"而不是"一次性的 prompt"）可能会成为下一个爆发点。
  5. 企业落地远未到饱和。2026 年的 Agent 应用主要集中在客服、代码、营销，金融、医疗、法律等强监管行业的 Agent 仍是早期。

2.11 本章小结

  1. Agent 的历史比 LLM 长 56 年——从 1966 年的 ELIZA 开始，到 2022 年 ChatGPT 才真正点燃第三次浪潮。
  2. 60 年里"Agent" 这个词的语义变了 5 次——它是愿景概念，不是技术概念。
  3. 1960s 的两个里程碑：ELIZA（对话 Agent 的祖先）和 Shakey（具身 Agent 的祖先）至今仍有现实意义。
  4. 1980s-1990s 的"智能体理论黄金十年" 为今天的术语表和架构思想（BDI、合同网、Society of Mind）打下了基础。
  5. Siri (2011) 和 Alexa (2014) 不是 Agent——它们是"命令式助手"，但它们让"和机器对话"成了日常，为 2023 年的 LLM Agent 铺平了心理基础。
  6. AlphaGo (2016) 给 Agent 行业最大的礼物是"信心"——证明"学习 + 搜索" 组合能击败人类顶尖高手。
  7. 2023 年的 AutoGPT/BabyAGI 是"第一次 Agent 狂热"——demo 惊艳，产品失败。但它催生了 AgentBench、SWE-bench 等关键评测。
  8. 2024 年是"落地年"——Computer Use、o1、MCP、Devin 一起把 Agent 从 demo 推进到产品。
  9. 2025 年是"标准化年"——MCP（工具）+ A2A（Agent）+ ADK（开发）三件套让"组合 Agent" 成为可能。
  10. 2026 年的判断：第三次浪潮是真的，但 Agent 还没通用化；协议标准化是最大的进步；企业落地远未到饱和。
