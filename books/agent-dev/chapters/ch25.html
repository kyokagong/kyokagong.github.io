25.2 RLHF 回顾——人类反馈强化学习

25.2.1 RLHF 起源

RLHF(Reinforcement Learning from Human Feedback)由 OpenAI 在 InstructGPT(2022)中推广,3 大阶段:SFT(监督微调)→ RM(奖励模型)→ PPO(策略优化)。

25.2.2 RLHF 3 阶段流程

阶段数据模型目标
1. SFT人工标注的(prompt, response)对基础 LLM学会基本指令遵循
2. RM人工对多个 response 排序奖励模型(LLM 顶上加回归头)学会"哪个回答更好"
3. PPO用 RM 作为奖励函数策略 LLM最大化期望奖励

25.2.3 RLHF 在 Agent 中的局限

  • 单轮假设——RLHF 假设一次 prompt 对应一次 response,Agent 多步规划天然违反
  • 离线训练——训练数据是静态的,无法反映真实部署分布
  • 奖励黑客——Agent 可能学到"如何骗过 RM"而非"如何完成任务"
  • 昂贵——人工标注成本 1-10 / 样本,百万样本起步

25.2.4 RLHF 在 Agent 的"妥协用法"

工程实践:把 Agent 多步轨迹截断为单步,每步单独 RLHF——损失 30-50% 的多步协同信号,但工程简单。

25.2.5 RLHF 在 Agent 中的"截断 RLHF"

工程模式:把 Agent 多步轨迹截断为单步,每步单独 RLHF——损失 30-50% 的多步协同信号,但工程简单。Anthropic Claude 早期版本采用此方案。

25.3 RLAIF / Constitutional AI——AI 反馈替代人类

25.3.1 RLAIF 核心思想

RLAIF(RL from AI Feedback):用另一个 LLM 替代人类标注员,生成偏好对。Anthropic 在 Constitutional AI(2022)中推广,核心理念:让 LLM 评判 LLM。

25.3.2 Constitutional AI 流程

1. SFT 同 RLHF
2. 让 LLM 根据"宪法"(一组规则,如"不要有害""不要歧视")对 response 打分
3. 用 LLM 的偏好训练 RM
4. PPO 训练策略模型

优势劣势
成本降至 1/100偏好质量受限于评判 LLM 能力
可扩展到百万样本评判 LLM 的偏见会被继承
无需人工标注复杂任务评判准确率 < 70%

25.3.3 Agent 中的适用场景

  • 安全对齐——ch23 5 层防御中的 L1 输入过滤可以用 RLAIF 训练
  • 工具选择——多工具场景下,RLAIF 比硬编码路由更灵活
  • 风格对齐——客服 / 教育 / 销售等风格敏感场景

25.3.4 RLAIF vs RLHF 工程权衡

维度RLHFRLAIF
单条标注成本1-100.01-0.1
标注速度100 条/小时/人10000 条/小时
准确率95%+70-85%
适用关键决策大规模粗筛

25.3.5 RLAIF 工程实践清单

1. 宪法规则——5-20 条简洁规则,避免歧义
2. 评判 LLM 选择——优先用 GPT-4 / Claude 4 Opus
3. few-shot 示例——给评判 LLM 5-10 个标注范例
4. 质量抽查——每周人工抽 100 条评估
5. 规则更新——每月 review 宪法规则

25.3.6 RLAIF 失败案例

某客服 Agent 用 RLAIF 后,学会"礼貌但答非所问"——评判 LLM 偏好礼貌,RLHF 把这种偏好放大。启示:RLAIF 需要明确的"业务指标"评判规则,纯风格评判易跑偏。

25.3.7 RLAIF 与 ch23 防御的关系

ch23 L4 防御层"输出过滤"可以用 RLAIF 训练——用一组有害/无害 response 对,让 LLM 学会过滤。这是 RLAIF 在工业 Agent 中最成熟的落地场景。

25.4 DPO 与直接偏好优化

25.4.1 DPO 数学直觉

DPO(Direct Preference Optimization, 2023)由 Stanford 提出:跳过 RM 和 PPO,直接用偏好数据训练策略模型。DPO loss:

L_{DPO} = -\log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)} \right)

其中 y_w 是首选 response,y_l 是次选 response。直觉:让好 response 的概率上升,坏 response 的概率下降。

25.4.2 DPO vs PPO

维度PPODPO
训练阶段3(SFT/RM/PPO)2(SFT/DPO)
需要 critic是否
训练稳定性易崩(奖励黑客)稳定
显存4×(策略+参考+RM+critic)2×(策略+参考)
效果略优90-95% PPO 效果
适用大模型 + 充足算力中小模型 + 快速迭代

25.4.3 DPO 在 Agent 中的离线训练应用

工程模式:收集 10k 失败 + 成功 Agent 轨迹对 → DPO 训练 → 部署。这是 2024-2026 最主流的 Agent 离线优化路径。

25.4.4 DPO loss 计算(mock 5 行)

import math


def dpo_loss(policy_logp_w, policy_logp_l, ref_logp_w, ref_logp_l, beta=0.1):

    """mock DPO loss(简化版)"""

    delta_w = policy_logp_w - ref_logp_w  # 首选概率提升

    delta_l = policy_logp_l - ref_logp_l  # 次选概率提升

    return -math.log(1 / (1 + math.exp(-beta * (delta_w - delta_l))))



# 模拟:首选 response 比次选多 2 nat 概率

loss = dpo_loss(policy_logp_w=-5.0, policy_logp_l=-7.0,

                ref_logp_w=-6.0,    ref_logp_l=-6.0)

print(f"DPO loss: {loss:.3f}")  # ≈ 0.049(越小越好)

25.4.5 DPO 在 2025 年的工业现状

  • Llama-3-Nemo(2024)——用 DPO 替代 RLHF,训练成本降低 60%
  • Mistral-Large-2(2024)——DPO + 在线微调,工业部署首选
  • Qwen-2.5(2024)——开源 SOTA,DPO + GRPO 双管齐下

25.4.6 DPO 的局限

DPO 在"明显好坏"场景效果拔群,但在"两个 response 都不错"时信号弱。生产实践中常配合 Pairwise RM + 在线 A/B 测试。

25.4.7 DPO 与 ch08 记忆系统的呼应

DPO 偏好对在工程上常常复用 ch08 的失败案例库——ch08 §8.4 把 Agent 失败 trace 存入长期记忆,ch25 DPO 直接从记忆库采样 (prompt, 失败 response, 正确 response) 三元组作为偏好对。这意味着 ch25 的训练数据基础设施 = ch08 的记忆系统 + ch22 的可观测性,无需新建数据管道。

25.4.8 DPO 训练失败的 3 大信号

工程诊断:训练中如果出现以下信号,说明 DPO 配置有问题。

信号原因修复
loss 不下降beta 太小 / 学习率过低beta 调到 0.1-0.5,lr 调到 1e-6 ~ 5e-6
loss 下降但评测掉偏好对有偏 / 过拟合增加偏好对多样性,加入 KL 约束
训练震荡数据乱序 / 批次大小不当shuffle + bs=32-64
这 3 个信号是 2024-2025 开源社区训练 DPO 的标准诊断清单——任何 Agent 团队训练 DPO 都该先打这份诊断表。

25.5 GRPO 与群组相对策略优化

25.5.1 GRPO 核心思想

GRPO(Group Relative Policy Optimization, DeepSeek R1 同款)由 DeepSeek 在 2025 年初提出。核心创新:用同一 prompt 的多个 response 之间的相对优势替代 critic。

25.5.2 GRPO 流程

1. 对同一 prompt 采样 G 个 response(比如 G=16)
2. 用 RM 给每个 response 打分
3. 在 G 个 response 内部做归一化作为优势
4. 用 PPO-style 更新(无 critic)

25.5.3 GRPO vs PPO

维度PPOGRPO
需要 critic是(价值网络)否
显存4×2×
优势估计TD(λ)组内相对
稳定性一般高
代表GPT-4 RLHFDeepSeek R1

25.5.4 GRPO 在 Agent 多步任务中的天然优势

Agent 多步任务天然有"组"概念——同一起点的多条不同执行轨迹。GRPO 不需要单独训 critic,直接用组内相对优势,工程友好得多。这就是为什么 DeepSeek R1 能在 Agent 任务上跑赢 GPT-4——GRPO 是关键。

25.5.5 GRPO 在 DeepSeek R1 中的关键作用

DeepSeek R1(2025)在数学/代码/Agent 任务上达到 GPT-4o 水平,核心是 GRPO + 大规模推理 trace。R1 训练流程:冷启动 SFT → GRPO 推理 RL → 拒绝采样 SFT → GRPO 全任务 RL。这个"二阶段 GRPO"是 2025 年开源 LLM 的标杆配方。

25.5.6 GRPO 在 Agent 中的实施清单

1. 同一起点采样 G=16-64 条 Agent 轨迹
2. 用 RM(可以是规则+LLM 混合)给每条打分
3. 组内归一化作为优势
4. PPO-style 更新(无 critic)
5. 监控 reward 方差,防止 collapse

25.5.7 GRPO 工程陷阱

  • 组大小 G——太小(<8)优势估计噪声大,太大(>64)训练慢。经验起始值 G=16(显存允许下尽量调大),DeepSeek R1 用 G=64
  • 温度参数——采样温度 0.7-1.2 区间最佳
  • reward shaping——稀疏 reward 必须加 dense 中间奖励

25.5.8 GRPO 与多 Agent 的天然契合

GRPO 的"同一起点多 response"在多 Agent 场景下天然存在——ch14 AutoGen 多 Agent 辩论、ch15 CrewAI 多角色任务,本身就产出多条候选轨迹。工程模式:把多 Agent 输出看作 GRPO 的"组",用业务指标打分,组内归一化后反向更新基础模型。这是 ch11-15 多 Agent + ch25 强化学习的工程交叉点。

25.6 Agent-Tuning——在 Agent trace 上微调

25.6.1 核心理念

Agent-Tuning(2024):把开源 LLM 在 Agent 多步轨迹数据上微调,使其具备 Agent 能力。代表数据集:AgentInstruct / ToolBench / AgentBank。

25.6.2 Agent-Tuning vs 普通 SFT

维度普通 SFTAgent-Tuning
训练数据单轮 (prompt, response)多步 (prompt, action, observation, action, ..., response)
数据量10k-100k50k-500k
训练后能力文本生成工具调用 + 规划 + 错误恢复
成本低中(需运行 Agent 收集轨迹)

25.6.3 7 步微调流程

1. 选择基础模型(Llama-3-8B / Qwen-7B)
2. 选择/构建 Agent trace 数据集
3. 数据清洗(过滤无效轨迹)
4. SFT 阶段 1:模仿教师(GPT-4)轨迹
5. SFT 阶段 2:加入成功/失败对比
6. DPO 阶段:用偏好数据进一步对齐
7. 评估 + 部署

25.6.4 GPT-4 → Llama-3 蒸馏典型轨迹

Llama-3-8B 在 100k GPT-4 Agent 轨迹上微调后,在 ToolBench 上达到 GPT-4 80% 水平,而推理成本仅 1/30。这是 2025 年中小公司自建 Agent 的主流路径。

25.6.5 Agent 蒸馏训练循环(mock)

def train_loop(agent, dataset, n_epochs=3):
    """mock 蒸馏训练循环"""
    for epoch in range(n_epochs):
        total_loss = 0
        for trace in dataset:  # trace 是 (prompt, steps, response)
            # 1. agent 模仿教师轨迹
            pred = agent(trace.prompt)
            # 2. 计算每步 loss
            loss = sum(step_loss(p, t) for p, t in zip(pred, trace.steps))
            total_loss += loss
            # 3. 反向传播(实际代码)
        print(f"Epoch {epoch+1}: avg loss = {total_loss/len(dataset):.3f}")
    return agent

25.7 在线学习——Agent 边跑边学

25.7.1 在线 vs 离线学习

维度离线学习在线学习
数据静态数据集生产 trace
更新频率周/月小时/天
风险低(可回滚)高(可能崩)

25.7.2 失败案例蒸馏

工程模式:Agent 失败时,把 (prompt, 错误信息, 正确做法) 三元组存入经验库,定期 DPO 微调。失败是最宝贵的老师。

25.7.3 经验回放(Replay Buffer)

借鉴深度强化学习的 DQN,Agent 训练时从 buffer 中采样历史轨迹,避免"灾难性遗忘"。

25.7.4 在线 RLHF

工业实践:Agent 部署后,部分请求(比如 5%)让人工实时评分,用这些分数持续微调模型。5% 标注 + 95% 自动化是成本-效果甜区。注:5% 是 OpenAI / Anthropic 公开博客披露的工业经验值,具体数值取决于业务规模。

25.7.5 经验回放 buffer(mock)

from collections import deque
import random


class ReplayBuffer:

    def __init__(self, capacity=10000):

        self.buffer = deque(maxlen=capacity)



def push(self, trace):

        """trace: (prompt, steps, response, reward)"""

        self.buffer.append(trace)



def sample(self, batch_size=32):

        return random.sample(self.buffer, min(batch_size, len(self.buffer)))



# 模拟 1000 条轨迹,采样 32 条训练

buffer = ReplayBuffer()

for i in range(1000):

    buffer.push((f"prompt_{i}", [f"step_{i}"], f"resp_{i}", random.random()))

batch = buffer.sample(32)

print(f"Sampled {len(batch)} traces for training")

25.7.6 4 大风险

1. 数据分布漂移——在线数据可能与训练数据分布差异大
2. 奖励黑客——Agent 学会"如何拿高分"而非"如何做好"
3. 评测失真——在线 A/B 测试周期长,难以快速迭代
4. 回滚困难——在线模型崩了可能影响生产

25.7.7 在线学习部署清单

25.8.1 Self-Refine 回顾

25.8.2 Constitutional Self-Critique

结合 ch23 安全 + ch25 RLAIF:Agent 根据宪法规则自我批评,过滤有害输出。这是 ch23 L1-L5 防御 L4 的工程实现。

25.8.3 失败重试 + 案例入库

工业模式:Agent 失败 → 自动重试 3 次(不同 prompt 变体)→ 仍失败 → 入库供下次训练。

25.8.4 自我批评循环(mock)

def self_critique_loop(agent, prompt, max_iter=3):
    """mock 自我批评循环"""
    response = agent(prompt)
    for i in range(max_iter):
        critique = agent.critique(prompt, response)
        if critique.is_satisfied:
            return response
        response = agent.improve(prompt, response, critique)
    return response  # 最多 3 轮


# 模拟:首版不满意 → 改进 → 第二版通过

class MockAgent:

    def __init__(self, name): self.name = name; self.calls = 0

    def __call__(self, p): self.calls += 1; return f"resp_{self.calls}"

    def critique(self, p, r):

        class C: 

            is_satisfied = self.calls >= 2  # 第二次满意

        return C()

    def improve(self, p, r, c): return f"{r}_v2"



result = self_critique_loop(MockAgent("a"), "test")

print(result)  # "resp_1_v2"
