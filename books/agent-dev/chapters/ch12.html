12.1 引子：从"手写 JSON"到"标准化协议"

12.1.1 ch11 留下的 3 个未解问题

ch11 的 4 大模式（Supervisor / Crew / Pipeline / Debate）都假设了一个前提：Agent 之间能用 JSON 互相发消息。但 JSON 本身不是协议——只有"消息里每个字段代表什么 + 失败时怎么重试 + 跨语言怎么互解析"才构成协议。

回头看 ch11 的 mock 实现，会发现 3 个未解问题：

问题 ch11 的解决方案 生产环境会怎样
工具调用协议 worker.tool_call({"name": "search", "args": {...}}) 手写 dict 跨进程 / 跨语言时 dict 的字段名/嵌套层不统一 → 解析失败
Agent 间通信协议 agent.send_message({"role": "researcher", "content": "..."}) 手写 接收方不知道 role 枚举有几种、content 是 str 还是 list
跨厂商互通 全部 mock，假设都是 Python in-process OpenAI Agent 想调用 Anthropic Agent？字段不兼容

结论：ch11 的 4 大模式解决了"协作的拓扑结构"问题，没有解决"通信的协议标准"问题——而后者是从 demo 走向生产的关键一步。

12.1.2 2024-2025 协议层标准化浪潮的 3 大推力

12.2 MCP（Model Context Protocol）——LLM 调用工具的标准

12.2.1 MCP 是什么

MCP = Model Context Protocol——Anthropic 在 2024-11 提出的开放协议，专门解决 LLM 调用工具的标准化问题。核心理念：

把"工具"抽象成 MCP Server，把"使用工具的 LLM"抽象成 MCP Client。Client 和 Server 之间用 JSON-RPC 2.0 通信。一次实现，所有兼容 MCP 的 LLM（Claude / GPT / Gemini）都能用。

MCP 类比 USB-C：之前每个工具（数据库 / 文件系统 / API）都要给每家 LLM 写适配器（4 工具 × 3 LLM = 12 套代码），MCP 之后工具写 1 套 MCP Server，所有 LLM 通过标准协议调用。

12.2.2 MCP 三大原语

原语 作用 类比 示例
Tools LLM 可调用的"动作"（带副作用） HTTP POST search_web(query) / send_email(to, body) / query_db(sql)
Resources LLM 可读取的"数据"（只读） HTTP GET file:///report.pdf / postgres://users/schema / git://repo/HEAD/readme
Prompts LLM 可选的"预制 prompt 模板" 模板库 /summarize prompt 模板 / /extract_entities prompt 模板

关键区别：Tools 改变世界状态（写 DB / 发邮件），Resources 只读世界状态（读文件 / 读 schema），Prompts 是 LLM 端的辅助。

12.2.3 MCP 架构


┌────────────────────────┐                    ┌────────────────────────┐
│  MCP Client (LLM 端)    │                    │  MCP Server (工具端)     │
│  ┌──────────────────┐  │   JSON-RPC 2.0      │  ┌──────────────────┐  │
│  │ Claude / GPT      │  │   over stdio/SSE/HTTP│  │ Tools             │  │
│  │ MCP Client SDK    │◄─┼──────────────────────┼─►│ Resources         │  │
│  │ (Python / TS / Go) │  │                    │  │ Prompts           │  │
│  └──────────────────┘  │                    │  └──────────────────┘  │
└────────────────────────┘                    └────────────────────────┘

通信方式 3 种：

  • stdio（标准输入/输出）—— 本地进程间通信，最常用
  • SSE（Server-Sent Events）—— HTTP 长连接，远程服务器
  • HTTP（streamable HTTP）—— 2025 新增，支持双向流

"""
最小可运行的 MCP client-server 演示
无需 pip install —— 完全用标准库模拟 JSON-RPC 2.0 协议
"""

import json
import subprocess
import sys
from typing import Any, Dict, List

# ===== MCP Server 端 =====

MCP_SERVER_CODE = '''
import json, sys

# 1. 声明能力（Server Capabilities）
SERVER_INFO = {
    "protocolVersion": "2024-11-05",
    "serverInfo": {"name": "demo-mcp-server", "version": "1.0.0"},
    "capabilities": {"tools": {}, "resources": {}, "prompts": {}}
}

# 2. 注册 3 个 Tools
TOOLS = [
    {
        "name": "get_weather",
        "description": "查询指定城市的天气",
        "inputSchema": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "城市名"}},
            "required": ["city"]
        }
    },
    {
        "name": "search_docs",
        "description": "在本地文档库中搜索关键词",
        "inputSchema": {
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "top_k": {"type": "integer", "default": 3}
            },
            "required": ["query"]
        }
    },
    {
        "name": "send_email",
        "description": "发送邮件（mock，不真发）",
        "inputSchema": {
            "type": "object",
            "properties": {
                "to": {"type": "string"},
                "subject": {"type": "string"},
                "body": {"type": "string"}
            },
            "required": ["to", "subject", "body"]
        }
    }
]

# 3. Tool 实现（mock）
def tool_get_weather(args):
    return {"city": args["city"], "temp": 22, "condition": "晴"}

def tool_search_docs(args):
    docs = ["MCP 是 LLM 调用工具的标准协议", "A2A 是 Agent 间的通信协议",
            "JSON-RPC 2.0 是 MCP 的传输层"]
    q = args["query"]
    matches = [d for d in docs if any(w in d for w in q.split())]
    return {"results": matches[:args.get("top_k", 3)]}

def tool_send_email(args):
    return {"status": "sent", "to": args["to"], "subject": args["subject"]}

TOOL_DISPATCH = {
    "get_weather": tool_get_weather,
    "search_docs": tool_search_docs,
    "send_email": tool_send_email,
}

# 4. JSON-RPC 2.0 消息循环
def handle_request(req):
    method = req.get("method")
    params = req.get("params", {})
    req_id = req.get("id")

    if method == "initialize":
        return {"jsonrpc": "2.0", "id": req_id, "result": SERVER_INFO}
    elif method == "tools/list":
        return {"jsonrpc": "2.0", "id": req_id,
                "result": {"tools": TOOLS}}
    elif method == "tools/call":
        name = params["name"]
        args = params.get("arguments", {})
        if name not in TOOL_DISPATCH:
            return {"jsonrpc": "2.0", "id": req_id,
                    "error": {"code": -32601, "message": f"Tool {name} not found"}}
        try:
            result = TOOL_DISPATCH[name](args)
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"content": [{"type": "text", "text": json.dumps(result, ensure_ascii=False)}]}}
        except Exception as e:
            return {"jsonrpc": "2.0", "id": req_id,
                    "error": {"code": -32603, "message": str(e)}}
    else:
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method {method} not found"}}

# 5. stdio 主循环
for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    try:
        req = json.loads(line)
        resp = handle_request(req)
        print(json.dumps(resp, ensure_ascii=False), flush=True)
    except Exception as e:
        err = {"jsonrpc": "2.0", "id": None,
               "error": {"code": -32700, "message": f"Parse error: {e}"}}
        print(json.dumps(err, ensure_ascii=False), flush=True)
'''

# ===== MCP Client 端 =====

class MCPClient:
    """简化版 MCP Client（用 subprocess + stdio）"""
    def __init__(self, server_script: str):
        self.proc = subprocess.Popen(
            [sys.executable, "-c", server_script],
            stdin=subprocess.PIPE, stdout=subprocess.PIPE,
            stderr=subprocess.PIPE, text=True, bufsize=1
        )
        self.req_id = 0
        self._initialize()

    def _send(self, method: str, params: Dict = None) -> Dict[str, Any]:
        self.req_id += 1
        req = {"jsonrpc": "2.0", "id": self.req_id, "method": method, "params": params or {}}
        self.proc.stdin.write(json.dumps(req, ensure_ascii=False) + "\n")
        self.proc.stdin.flush()
        line = self.proc.stdout.readline()
        return json.loads(line)

    def _initialize(self):
        info = self._send("initialize")
        print(f"[MCP] 连接 server: {info['result']['serverInfo']}")

    def list_tools(self) -> List[Dict]:
        resp = self._send("tools/list")
        return resp["result"]["tools"]

    def call_tool(self, name: str, arguments: Dict) -> Dict:
        resp = self._send("tools/call", {"name": name, "arguments": arguments})
        if "error" in resp:
            return {"error": resp["error"]}
        return json.loads(resp["result"]["content"][0]["text"])

    def close(self):
        self.proc.stdin.close()
        self.proc.terminate()

# ===== Demo 跑通 =====

if __name__ == "__main__":

    try:

12.3 A2A（Agent-to-Agent）——Agent 间的发现与协作

12.3.1 A2A 是什么

A2A = Agent-to-Agent——Google 在 2025-04 提出的开放协议，专门解决 Agent 之间的发现、协商、任务委托问题。MCP 解决"LLM 调工具"，A2A 解决"Agent 调 Agent"。

核心实体：

  • Agent Card —— 一张 JSON 卡片，描述"我是谁 / 我能干什么 / 怎么联系我"，类似"Agent 的名片"
  • Task —— Agent 之间的任务单元，有完整生命周期（submitted → working → input-required → completed/failed/canceled）
  • Message / Part —— Task 内的消息载荷，Message 含多个 Part（text / file / data）

12.3.2 A2A 完整工作流


1. Agent A 想要找能干的 Agent → 读 A2A Registry / 已知 Agent Card URL
2. Agent A 拿 Agent B 的 Card → 知道 B 干啥、参数格式
3. Agent A 发 "tasks/send" 给 Agent B → B 接收任务
4. Agent B 工作过程中可能 "input-required" → A 提供补充输入
5. Agent B 完成 → 返回 artifacts（最终产出） + status="completed"

"""
A2A 风格的 Agent 发现 + 任务委派 mock
演示 Agent Card 注册、发现、tasks/send 全流程
"""

import json
import time
import uuid
from typing import Dict, List, Optional

# ===== 1. Agent Card 注册中心 =====

AGENT_REGISTRY: Dict[str, dict] = {}

def register_agent(card: dict):
    """注册一个 Agent（生产环境是 A2A Registry 服务）"""
    AGENT_REGISTRY[card["url"]] = card
    print(f"[Registry] 已注册 Agent: {card['name']} @ {card['url']}")

def discover_agents(skill: Optional[str] = None) -> List[dict]:
    """发现具备某技能的 Agent（生产环境是 GET /.well-known/agent.json）"""
    results = []
    for url, card in AGENT_REGISTRY.items():
        if skill is None or any(skill in s["id"] for s in card.get("skills", [])):
            results.append(card)
    return results

# ===== 2. Task 生命周期管理 =====

TASK_STATES = ["submitted", "working", "input-required", "completed", "failed", "canceled"]

class Task:
    def __init__(self, agent_url: str, message: dict):
        self.id = str(uuid.uuid4())[:8]
        self.agent_url = agent_url
        self.message = message
        self.status = "submitted"
        self.artifacts: List[dict] = []
        self.history: List[dict] = [{"status": "submitted", "ts": time.time()}]

    def transition(self, new_status: str):
        if new_status not in TASK_STATES:
            raise ValueError(f"非法状态: {new_status}")
        self.status = new_status
        self.history.append({"status": new_status, "ts": time.time()})

# ===== 3. Remote Agent 端（mock）=====

class RemoteAgent:
    """模拟一个远程 Agent，接收 tasks/send，处理后返回 artifacts"""
    def __init__(self, card: dict):
        self.card = card
        self.tasks: Dict[str, Task] = {}

    def handle_task(self, task: Task):
        """执行任务（真实环境是 HTTP POST {agent_url}/tasks/send）"""
        self.tasks[task.id] = task
        task.transition("working")
        # 模拟处理
        time.sleep(0.01)
        # 根据 skill 执行不同逻辑
        skill = task.message.get("skill", "")
        if skill == "arxiv-search":
            artifacts = [{"type": "papers", "data": [
                {"title": "MCP: An Open Protocol for LLM-Tool Integration", "year": 2024},
                {"title": "A2A: Agent-to-Agent Protocol", "year": 2025}
            ]}]
        elif skill == "summarize":
            artifacts = [{"type": "summary", "data": "本综述覆盖 2 篇核心论文..."}]
        else:
            artifacts = [{"type": "text", "data": f"Agent {self.card['name']} 收到任务: {task.message}"}]
        task.artifacts = artifacts
        task.transition("completed")

# ===== 4. Client 端：发现 + 委派 =====

class A2AClient:
    def __init__(self):
        self.registry = AGENT_REGISTRY
        self.remote_agents: Dict[str, RemoteAgent] = {}

    def register(self, card: dict):
        register_agent(card)
        self.remote_agents[card["url"]] = RemoteAgent(card)

    def discover(self, skill: str) -> List[dict]:
        return discover_agents(skill)

    def send_task(self, agent_url: str, message: dict) -> Task:
        if agent_url not in self.remote_agents:
            raise ValueError(f"Agent {agent_url} 未注册")
        task = Task(agent_url, message)
        self.remote_agents[agent_url].handle_task(task)
        return task

12.6 协议层 5 大坑

12.6.1 坑 1：MCP 工具描述不一致

症状：MCP Server 暴露了 query_db(sql)，但 description 写的是"查询数据库"，没有说支持哪些 SQL 语法、返回什么字段。LLM 看到这种模糊描述，要么不调、要么调错。

根因：MCP Server 的 inputSchema 是 JSON Schema，质量完全靠开发者。协议不强制每个参数写 description。

修复：


{
  "name": "query_db",
  "description": "查询 PostgreSQL 数据库。支持 SELECT，参数化查询防注入。返回 [{column: value}] 格式。",
  "inputSchema": {
    "type": "object",
    "properties": {
      "sql": {"type": "string", "description": "参数化 SQL，例如 'SELECT * FROM users WHERE id = $1'"},
      "params": {"type": "array", "description": "SQL 参数列表", "items": {"type": "string"}}
    },
    "required": ["sql", "params"]
  }
}

检验方法：让 LLM 调一次，如果调对 → 描述够好；调错 → 加 description。

12.6.2 坑 2：A2A 兼容性碎片化

症状：A2A 协议 2025-04 才发布 v0.1，到 2025-09 已经出现 3 个不兼容版本（v0.1 / v0.2 / v0.3）。不同厂商实现的 A2A Client / Server 之间经常握手失败。

根因：标准化早期协议版本号频繁变更，所有厂商都在追规范但节奏不一。

修复：

  1. 生产环境固定一个版本（如 v0.2.1），所有 Agent 统一
  2. 加版本协商层 —— 握手时 Client 声明支持的版本，Server 选最高兼容的
  3. 抽象一层 wrapper —— 不要直接用官方 SDK，而是封装一层（未来换版本只改 wrapper）

12.6.3 坑 3：协议版本管理

症状：MCP 协议 2024-11 → 2025-06 升级了 3 次，每次升级可能加新字段、改默认行为。你的 MCP Server 跑在 v2024-11-05，Client 跑在 v2025-06-18，可能莫名其妙调用失败。

根因：协议版本号在 initialize 响应里返回（protocolVersion 字段），但很多代码不检查。

修复：


def _initialize(self):
    info = self._send("initialize")
    server_version = info["result"]["protocolVersion"]
    if not is_compatible(server_version, SUPPORTED_VERSIONS):
        raise RuntimeError(f"Server protocol {server_version} 不兼容")

12.6.4 坑 4：安全边界

症状：MCP Server 暴露 send_email(to, body)，LLM 在用户引导下发了 100 封垃圾邮件。A2A Agent 接收了恶意 Agent 的 task，执行了破坏性操作。

根因：协议本身不强制鉴权 / 限流 / 内容审计。

修复：

  1. MCP Server 侧：加调用频率限制（每分钟 10 次）、敏感操作二次确认（send_email 前要求 user 确认）
  2. A2A 侧：必须 OAuth2 鉴权、Task payload 加签名、接收方用沙箱环境执行
  3. 审计层：所有 Tool / Task 调用记日志，事后审计

12.6.5 坑 5：协议开销

症状：MCP 比直接调 Python 函数慢 5-10 倍（subprocess + JSON 序列化 + 进程间通信），A2A 比 in-process 消息慢 50-100 倍（HTTP + JSON-RPC + 网络往返）。

根因：协议开销 = 序列化 + 传输 + 解析，跨进程 / 跨网络必然慢。

修复：

  • 本地高频调用不要用 MCP —— 直接 Python import
  • 远程低频调用放心用 A2A —— 50ms 延迟不影响 5s 任务
  • 批量调用 —— MCP 一次 tools/call 调一个工具，A2A 一次任务多 artifact 一起回

12.9.1 为什么需要 FastMCP

  • 第 1-10 个 MCP Server：直接用 mcp.server.fastmcp 装饰器
  • 第 11+ 个 MCP Server：封装到内部框架，共享鉴权、日志、限流中间件

12.9.2 80 行完整 FastMCP Server：模拟 3 个工具


# ch12_fastmcp_server.py
# 真实环境: pip install mcp
# 运行: python3 ch12_fastmcp_server.py
#       （MCP Client 通过 stdio 启动此进程，然后 JSON-RPC 通信）
# 本示例 mock 实现演示完整协议流程

import json
import sys
from typing import Any, Dict, List

# ===== 1. FastMCP 装饰器（mock 真实 mcp.server.fastmcp 的 API）=====

class FastMCP:
    def __init__(self, name: str):
        self.name = name
        self.tools: Dict[str, Dict[str, Any]] = {}
        self.resources: Dict[str, str] = {}

    def tool(self, name: str = None):
        """装饰器：把函数注册为 MCP Tool"""
        def decorator(func):
            tool_name = name or func.__name__
            # 自动从函数签名生成 JSON Schema
            import inspect
            sig = inspect.signature(func)
            params = {}
            required = []
            for pname, param in sig.parameters.items():
                if param.annotation is inspect.Parameter.empty:
                    ptype = "string"
                elif param.annotation == int:
                    ptype = "integer"
                elif param.annotation == float:
                    ptype = "number"
                else:
                    ptype = "string"
                params[pname] = {"type": ptype, "description": f"参数 {pname}"}
                if param.default is inspect.Parameter.empty:
                    required.append(pname)
            self.tools[tool_name] = {
                "name": tool_name,
                "description": func.__doc__ or "",
                "inputSchema": {"type": "object", "properties": params, "required": required},
                "func": func,
            }
            return func
        return decorator

    def resource(self, uri: str):
        """装饰器：把 URI 注册为 MCP Resource"""
        def decorator(func):
            self.resources[uri] = func()
            return func
        return decorator

    def run_stdio(self):
        """stdin/stdout JSON-RPC 主循环（生产用 mcp 库实现）"""
        print(f"[FastMCP] Server '{self.name}' 启动，等待 Client 连接...", file=sys.stderr)
        for line in sys.stdin:
            try:
                req = json.loads(line)
                resp = self._handle(req)
                sys.stdout.write(json.dumps(resp) + "\n")
                sys.stdout.flush()
            except Exception as e:
                err = {"jsonrpc": "2.0", "id": None, "error": {"code": -32603, "message": str(e)}}
                sys.stdout.write(json.dumps(err) + "\n")
                sys.stdout.flush()

    def _handle(self, req: Dict[str, Any]) -> Dict[str, Any]:
        method = req.get("method")
        req_id = req.get("id")
        if method == "initialize":
            return {"jsonrpc": "2.0", "id": req_id, "result": {
                "protocolVersion": "2025-06-18",
                "serverInfo": {"name": self.name, "version": "1.0.0"},
                "capabilities": {"tools": {}, "resources": {}}
            }}
        elif method == "tools/list":
            tools_list = [{"name": t["name"], "description": t["description"],
                           "inputSchema": t["inputSchema"]} for t in self.tools.values()]
            return {"jsonrpc": "2.0", "id": req_id, "result": {"tools": tools_list}}
        elif method == "tools/call":
            params = req.get("params", {})
            tool_name = params.get("name")
            args = params.get("arguments", {})
            if tool_name not in self.tools:
                return {"jsonrpc": "2.0", "id": req_id, "error": {"code": -32601, "message": f"Tool {tool_name} not found"}}
            try:
                result = self.tools[tool_name]["func"](**args)
                return {"jsonrpc": "2.0", "id": req_id, "result": {
                    "content": [{"type": "text", "text": str(result)}]
                }}
            except Exception as e:
                return {"jsonrpc": "2.0", "id": req_id, "error": {"code": -32603, "message": str(e)}}
        return {"jsonrpc": "2.0", "id": req_id, "error": {"code": -32601, "message": f"Method {method} not found"}}

12.10 协议层 6 个常见疑问 FAQ

12.10.1 Q1: 我应该用 MCP 还是直接用厂商 SDK？

A: 看调用频率。

场景 推荐 原因
每天调 1000+ 次同一工具 直接 SDK（跳过协议） 协议开销 5-10 倍不可接受
每天调 10-100 次不同工具 MCP 一套协议覆盖所有工具
工具需要跨 LLM 厂商 MCP MCP 一次实现，Claude / GPT / Gemini 都能用
LLM 是固定的（如只用 Claude） 直接 Claude SDK 没必要加协议层

12.10.2 Q2: A2A 协议会不会取代 MCP？

A: 不会，两者定位互补。

  • MCP 解决"LLM ↔ 工具"——是垂直通信（一个调用方对一个被调用方）
  • A2A 解决"Agent ↔ Agent"——是水平通信（多个对等方互调）
  • 真实生产 = MCP（工具层）+ A2A（协作层），两者不互斥

类比：HTTP 不会取代 SQL——一个管传输、一个管数据，不在同一抽象层。

12.10.3 Q3: 自建 Agent 不暴露 A2A 端点，会被淘汰吗？

A: 短期不会，长期会"协议孤岛化"。

  • 短期（2026-2027）：自建 Agent 用 JSON + REST 仍能跑通——多数企业内 Agent 协作是预定义的
  • 长期（2028+）：跨厂商 Agent 互操作需求增长时，不暴露 A2A 端点 = 别的 Agent 找不到你 = 生态孤立
  • 建议：2026 年新项目默认实现 A2A 端点（增量成本 < 5%），老项目逐步加

12.10.4 Q4: MCP 协议安全吗？

A: 协议本身安全（基于 JSON-RPC + 鉴权可选），但 Server 实现安全性完全靠开发者。

风险 MCP 是否解决 开发者必须做
Tool 描述歧义导致 LLM 调错 ❌ 写好 description 和 inputSchema
Tool 执行破坏性操作 ❌ 加二次确认 / 限流
Server 被恶意 Client 攻击 ❌ 加鉴权 + 输入验证
敏感数据泄露 ❌ 加密传输 + 审计日志

核心：MCP 是"标准化通信层"，不是"安全沙箱"。生产部署 MCP Server 必须自己加 4 层防护：鉴权 / 限流 / 审计 / 沙箱。

12.10.5 Q5: 协议性能开销具体多少？

A: 5-100 倍，取决于部署方式。

估算口径：对比基准 = 直接 SDK 调用（Python in-process）。stdio MCP 慢 5-10 倍（进程启动 + 序列化），A2A HTTP 委派慢 50-100 倍（多次网络往返）。对比真实生产需求（单次调用 50-200ms 容忍），stdio / SSE 几乎无感，A2A 在长任务（>10s）也可接受。

部署方式 协议开销 原因
stdio（本地） 5-10 倍 进程启动 + JSON 序列化
SSE（HTTP 长连接） 20-50 倍 网络往返 + SSE 帧解析
streamable HTTP 10-30 倍 HTTP/2 多路复用 + 双向流
A2A（HTTP 任务委派） 50-100 倍 多次往返 + 状态轮询

优化方向：

  • 本地高频调用 → 直接 Python import（0 开销）
  • 远程低频调用 → 接受 50ms 延迟
  • 批量调用 → 1 次任务传 N 个参数，减少往返

12.10.6 Q6: 现在学 MCP / A2A 来得及吗？

A: 正是时候——2025-2026 是"协议层红利期"。

  • 2024-11 前：没协议，开发者各写各的
  • 2025-04 后：协议发布，懂协议的开发者稀缺
  • 2026 预测：80% 招聘要求"熟悉 MCP 或 A2A"
  • 2027+：协议稳定成"必会技能"（类似"懂 HTTP"）

学习路径：

  1. 第 1 周：读 MCP 官方文档（modelcontextprotocol.io） + 跑通 stdio demo
  2. 第 2 周：实现 1 个自定义 MCP Server（封装你常用的 API）
  3. 第 3 周：读 A2A 规范 + 实现 1 个 A2A 端点
  4. 第 4 周：搭一个"MCP Server + A2A Agent"的最小混搭系统
  5. 第 2 个月：贡献 1 个开源 MCP Server / A2A Agent
