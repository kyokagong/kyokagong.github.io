第 14 章 · 用 AutoGen 构对话式多 Agent——对话驱动的多 Agent 编排

第 11 种 inline SVG 形态学 — 对话总线 + 多角色对话编排（vs ch11 hub-and-spoke 4 模式 / ch13 节点-边-状态三元组）

承上启下：ch13 讲了 LangGraph 的"图编排"——把工作流显式建模成 State + Nodes + Edges。但多 Agent 协作不一定都是图——很多时候是多角色对话（研究员、作家、评论家轮番发言）。这种场景用 LangGraph 写就得手撸节点+边+条件路由，而 AutoGen（Microsoft Research 出品）直接给你"对话总线"——GroupChat 帮你管谁接下来说什么。

>

本章拆解 AutoGen 的 2 大核心角色 + GroupChat 编排 + ReAct/Supervisor 实战——读完能用 AutoGen 把 ch11 模式（Supervisor / Crew / Debate）中的"对话型"实现快速落地。

14.1 引子：ch13 留下的 2 个问题 + AutoGen 的回答

14.1.1 ch13 留下的 2 个落地问题

ch13 解决了"工作流编排"问题，但留下了 2 个场景用 LangGraph 不顺手：

场景 ch13 LangGraph 怎么写 痛点
辩论（正方/反方/裁判） 同样得手撸 N 节点 + 双向边 + 终止条件 状态膨胀（所有发言累积在 messages），没有内置"哪一方该说"机制

结论：当 Agent 协作是多角色对话（不是"流程图"）时，对话总线比图编排更自然。

14.1.2 AutoGen 的回答——"让对话成为一等公民"

AutoGen v0.4（2024-Q4 重写版）的核心抽象：

  • Actor Model 架构（不是图！）—— 每个 Agent 是独立 actor，通过消息总线通信
  • GroupChat 内置 messages 列表——所有发言累积，对所有参与者可见
  • GroupChatManager 自动选下一 speaker——不用手撸 if-else 路由
  • is_termination_msg 终止判定——任意 Agent 都可以发"收工"消息
  • UserProxyAgent 人机协作——把人类作为对话的一等公民

一句话总结：AutoGen = 显式对话 + 隐式控制流 = 多角色协作的最短代码路径。

核心差异：LangGraph 是"先有图再跑对话"，AutoGen 是"直接跑对话图自己长出来"。前者工程师友好，后者产品/业务友好。

14.2.2 v0.4 架构：Actor Model + 消息总线

AutoGen v0.4 的核心是 Actor Model（1973 年 Carl Hewitt 提出的并发计算模型）：

  • 每个 Agent 就是一个 Actor —— 独立状态机，对外只通过消息交互
  • 消息总线（RoutedAgent） —— 所有消息通过 autogen-core 的 runtime 路由
  • 跨语言 —— Python Agent 和 .NET Agent 可以互相发消息（共享 protobuf 协议）
  • 可观测 —— 整个对话流可被 OpenTelemetry 采集

为什么 Actor Model 比图更好？ 当 Agent 数量从 3 个涨到 30 个、且互相通信关系是动态的（图边动态变化）时，Actor Model 的"消息地址"机制比图的"边"更灵活。但反过来——如果你的工作流是固定的、显式的、需可视化，LangGraph 的图更直接。

14.3 2 大核心角色：AssistantAgent + UserProxyAgent

14.3.1 AssistantAgent：LLM 角色

AssistantAgent 是"会说人话 + 能调工具"的 Agent：


from autogen_agentchat.agents import AssistantAgent

agent = AssistantAgent(
    name="assistant",                    # 必填，对话中显示
    model_client=model_client,           # 必填，LLM 客户端（OpenAI/Anthropic/Mock）
    system_message="你是一个助手。",     # 可选，system prompt
    tools=[my_tool],                     # 可选，工具列表（Function Calling）
    description="短描述，给其他 Agent 看", # 可选
)

关键点：

  • name 必须全局唯一（同一 GroupChat 内）
  • system_message 是该 Agent 的"人设"
  • tools 自动转成 OpenAI / Anthropic 的 function calling schema
  • description 在 SelectorGroupChat 选 speaker 时会被 LLM 看到

14.3.2 UserProxyAgent：人/工具/代码执行代理

UserProxyAgent 是"人 + 工具 + 代码执行"的复合代理：


from autogen_agentchat.agents import UserProxyAgent

# 模式 1：作为人机界面（接收人类输入）
human = UserProxyAgent(
    name="human",
    input_mode="console",     # 等待用户输入
)

# 模式 2：作为代码执行器（在 Docker / 本地跑代码）
executor = UserProxyAgent(
    name="executor",
    code_execution_config={
        "executor": "docker",   # 或 "local"
        "image": "python:3.12", # Docker 镜像
    },
)

# 模式 3：纯占位（不执行，仅作为对话参与者）
placeholder = UserProxyAgent(
    name="placeholder",
    input_mode="never",        # 不等待输入
)

3 种模式：

  • 人机界面：input_mode="console" 等待人类回复
  • 代码执行：在 Docker 或本地跑 LLM 生成的代码（v0.4 已移到独立 CodeExecutorAgent）
  • 纯占位：不执行任何事，仅作为对话角色

v0.4 vs v0.2 重要变化：UserProxyAgent 在 v0.4 中代码执行功能被拆到 CodeExecutorAgent（v0.2 用 code_execution_config 即可）。本章用 v0.4 写法。

14.3.3 Hello World：单 Assistant + 单 UserProxy 30 行

场景：让 LLM 助手回答"1+1=?"，人作为对话参与者。


import asyncio
from autogen_agentchat.agents import AssistantAgent, UserProxyAgent
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.conditions import MaxMessageTermination


# 模型客户端（实际用 OpenAIChatCompletionClient，这里 mock 演示）
from autogen_core.models import CreateResult, ModelInfo


class MockChatClient:
    """Mock LLM — 真实场景换 OpenAIChatCompletionClient(model="gpt-4o") 即可"""
    def __init__(self, response: str):
        self._response = response
        self.model_info: ModelInfo = {
            "vision": False, "function_calling": False, "json_output": False,
            "family": "mock", "structured_output": False, "multiple_system_messages": True,
        }

    async def create(self, messages, **kwargs) -> CreateResult:
        return CreateResult(
            content=self._response, finish_reason="stop",
            usage={"prompt_tokens": 5, "completion_tokens": 5}, cached=False,
        )
    async def close(self): pass


async def main():
    assistant = AssistantAgent(
        name="assistant",
        model_client=MockChatClient("1+1=2。"),
        system_message="你是一个数学助手。",
    )
    user = UserProxyAgent(name="user", input_mode="never")  # 纯占位

    team = RoundRobinGroupChat(
        participants=[assistant, user],
        termination_condition=MaxMessageTermination(max_messages=2),
    )

    result = await team.run(task="1+1=多少？")
    for m in result.messages:
        print(f"[{m.source}] {m.content}")


asyncio.run(main())

运行（venv 内）：python3 hello_autogen.py

输出：


[user] 1+1=多少？
[assistant] 1+1=2。

对照 LangGraph 30 行：AutoGen 版本代码更短、配置项更少——核心是"配置 Agent"而非"配置图"。

14.4 GroupChat 多 Agent 对话总线（核心）

14.4.1 GroupChat 是什么

GroupChat（在 v0.4 中对应 RoundRobinGroupChat / SelectorGroupChat） = 3 个或更多 Agent 共享一个 messages 列表，按规则轮番发言。

团队类 选下一 speaker 方式 适用场景
SelectorGroupChat LLM 选（让 GPT-4 看历史 + agent description 决定下一个） 动态决策（谁能回答就谁来）
Swarm Agent 自己决定（hand_off 消息） 类似 AutoGen v0.2 Swarm 范式
MagenticOneGroupChat 微软 Magentic-One 编排器 复杂多 Agent 任务（网页操作 + 文件 + 代码）

本章主要讲 RoundRobinGroupChat 和 SelectorGroupChat——前者是入门，后者是进阶。

14.4.2 GroupChat 完整 Hello World 50 行——3 角色写短文

场景：Researcher（研究员）+ Writer（作家）+ Critic（评论家）3 角色合作写一段 100 字的西湖历史短文。


import asyncio
from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.conditions import MaxMessageTermination
from autogen_core.models import CreateResult, ModelInfo


class CannedClient:
    """按调用次数返回预设 response — 不需要真 LLM"""
    def __init__(self, *responses: str):
        self._responses = list(responses)
        self._idx = 0
        self.model_info: ModelInfo = {
            "vision": False, "function_calling": False, "json_output": False,
            "family": "mock", "structured_output": False, "multiple_system_messages": True,
        }

    async def create(self, messages, **kwargs) -> CreateResult:
        text = self._responses[min(self._idx, len(self._responses) - 1)]
        self._idx += 1
        return CreateResult(
            content=text, finish_reason="stop",
            usage={"prompt_tokens": 10, "completion_tokens": len(text)}, cached=False,
        )
    async def close(self): pass


async def write_essay():
    # 3 个角色 — 每个有自己的 system_message + mock response
    researcher = AssistantAgent(
        name="Researcher",
        model_client=CannedClient(
            "调研：杭州西湖原为海湾，后成内陆湖；唐代白居易任杭州刺史修白堤。",
            "补充：北宋苏轼任杭州知州修苏堤，南宋形成'西湖十景'。",
        ),
        system_message="你是一个研究员，提供准确历史事实。",
    )
    writer = AssistantAgent(
        name="Writer",
        model_client=CannedClient(
            "西湖历史悠久，自唐宋以来便是文人墨客的圣地。",
            "西湖承载着白居易、苏轼的诗情，也见证了十景的诗意。",
        ),
        system_message="你是一个作家，把资料写成有文采的句子。",
    )
    critic = AssistantAgent(
        name="Critic",
        model_client=CannedClient(
            "建议加诗词引用（如苏轼'欲把西湖比西子'），更有文化氛围。",
            "现在好多了，可以收尾。",
        ),
        system_message="你是一个评论家，给改进建议。",
    )

    # 团队 — 3 角色轮转，最多 6 条消息（3 角色 × 2 轮）
    team = RoundRobinGroupChat(
        participants=[researcher, writer, critic],
        termination_condition=MaxMessageTermination(max_messages=6),
    )

    result = await team.run(task="合作写一段 100 字西湖历史短文。")
    print(f"\n=== 共 {len(result.messages)} 条消息 ===\n")
    for i, m in enumerate(result.messages):
        print(f"[{i}] [{m.source}] {m.content[:80]}")


asyncio.run(write_essay())

14.4.3 speaker selection 4 种策略

策略 实现类 选 speaker 方式 优点 缺点
LLM 选 SelectorGroupChat GPT-4 看历史 + 角色 description 选 动态、灵活 多花 1 次 LLM 调用
Agent 自决 Swarm 当前 Agent 发 HandoffMessage 自主决策 调试复杂（无全局视图）
Magentic-One 编排 MagenticOneGroupChat 微软 Magentic-One 编排器选 适合复杂任务 黑盒、依赖微软模型

90% 场景用 RoundRobinGroupChat 或 SelectorGroupChat 即可。Swarm 适合"每个 Agent 知道该交给谁"的场景（少用）；MagenticOneGroupChat 适合"我也不知道谁该做"的复杂任务。

14.4.4 GroupChat vs LangGraph Supervisor 哲学对比

维度 LangGraph Supervisor AutoGen GroupChat
中心化程度 强中心化（所有 Worker 必须听 Supervisor） 弱中心化（任何 Agent 都可以"插话"）
代码量 多（手撸 Supervisor 节点 + 路由） 少（配置 participants 即可）
可观测 强（图可视化 + LangSmith） 中（消息列表 + OpenTelemetry）
适合规模 3-10 个 Agent（多了 Supervisor 成瓶颈） 3-30 个 Agent（多 Agent 协作时不会卡 Manager）
哲学 "工程师画流程图" "业务写对话剧本"

经验法则：

  • 3-5 个固定角色、流程清晰 → AutoGen GroupChat
  • 多分支、长流程、需 checkpoint → LangGraph
  • 想给业务/PM 看懂流程 → AutoGen（代码即剧本）
  • 想给工程师精确控制 → LangGraph

14.5 GroupChatManager 与 speaker selection

14.5.1 GroupChatManager 自动选 speaker

GroupChatManager 是 v0.4 中管理对话流的内部组件（一般不直接用）。在 SelectorGroupChat 中：

  1. 把当前对话历史 + 所有 Agent 的 description 拼成 prompt
  2. 调一次 LLM 决定下一个 speaker
  3. 把选中的 Agent 加到消息队列，下一轮执行

示例：3 角色客服场景，Manager 选下一 speaker：


from autogen_agentchat.teams import SelectorGroupChat
from autogen_agentchat.conditions import MaxMessageTermination, TextMentionTermination

# 3 角色客服
classifier = AssistantAgent(
    name="Classifier", model_client=model_client,
    description="分类用户问题（账单/技术/退订）",
    system_message="把用户问题分到对应类别。",
)
billing_agent = AssistantAgent(
    name="BillingAgent", model_client=model_client,
    description="处理账单和付款问题",
    system_message="你是账单专家。",
)
tech_agent = AssistantAgent(
    name="TechAgent", model_client=model_client,
    description="处理技术支持问题",
    system_message="你是技术专家。",
)
supervisor = AssistantAgent(
    name="Supervisor", model_client=model_client,
    description="监督对话，当所有问题都回答完说 DONE",
    system_message="当用户问题全部回答完时回复 DONE。",
)

team = SelectorGroupChat(
    participants=[classifier, billing_agent, tech_agent, supervisor],
    termination_condition=TextMentionTermination("DONE"),  # 见 14.5.2
    max_turns=10,
)

14.5.2 TerminationCondition 4 种内置

终止条件 触发条件 适用
TextMentionTermination("DONE") 任意消息含 "DONE" 显式收工信号
FunctionCallTermination(func) 调了指定函数 "工具调用完即终止"
TokenUsageTermination(max_tokens) 累计 token ≥ 阈值 成本控制（生产必备）
TimeoutTermination(seconds) 超过 N 秒 防止长对话卡住
HandoffTermination(target) 移交给 target Agent Swarm 范式

可组合：MaxMessageTermination(20) | TextMentionTermination("DONE")——任一触发即终止。

14.5.3 对照 ch13 终止机制

ch13 LangGraph 终止 ch14 AutoGen 终止
should_continue 路由函数返回 END TerminationCondition 对象
GraphRecursionError（无限循环） MaxMessageTermination 自动防呆
手动 track_tokens（§13.6.3 实战） TokenUsageTermination 内置

AutoGen 在"防呆"上比 LangGraph 友好——LangGraph 需要手撸 should_continue 路由函数 + 手动 track tokens；AutoGen 一个 TerminationCondition 链搞定。

14.5.4 SelectorGroupChat vs RoundRobinGroupChat 选型决策

场景 推荐 理由
客服多分类路由（用户问题分到账单/技术/退订） SelectorGroupChat 动态决策，避免"用户问账单但轮到技术 Agent"
辩论（正方/反方/裁判） RoundRobinGroupChat 角色固定，强制轮流
数据流水线（清洗 → 分析 → 报告） RoundRobinGroupChat 步骤固定
创意头脑风暴（谁有新点子谁说） SelectorGroupChat 选有想法的 Agent
代码审查 + 自动测试 SelectorGroupChat 失败时让 "tester" 反复跑
超过 5 个 Agent 的大型协作 SelectorGroupChat 轮转 5+ Agent 等待时间太长，动态选更优

经验法则：先 RoundRobinGroupChat，跑通后再考虑 SelectorGroupChat——后者每轮多 1 次 LLM 调用（成本 + 200-500ms 延迟），但更灵活。

本节是"选哪种团队类"（RoundRobinGroupChat / SelectorGroupChat / Swarm / MagenticOneGroupChat），与 §14.5.2 终止条件是不同维度——前者决定"谁说"，后者决定"什么时候停"。选完团队类后，再用 MaxMessageTermination 等终止条件兜底。

14.6 完整 ReAct Agent 实战（ch13↔ch14 对照）

14.6.1 完整 ReAct Agent 80 行

场景：让 Agent 回答"北京今天需要带伞吗？"，需要先查天气，再决定是否提醒。


import asyncio
from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.conditions import MaxMessageTermination
from autogen_core.models import CreateResult, ModelInfo


# 工具定义（OpenAI / Anthropic 风格的 function calling schema）
TOOL_GET_WEATHER = {
    "name": "get_weather",
    "description": "查询城市天气",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "城市名"}},
        "required": ["city"],
    },
}

TOOL_SEND_REMINDER = {
    "name": "send_reminder",
    "description": "发送提醒到用户日历",
    "parameters": {
        "type": "object",
        "properties": {"content": {"type": "string", "description": "提醒内容"}},
        "required": ["content"],
    },
}


class ReactMockClient:
    """按调用次数返回 ReAct 3 步（mock 模式：Action + Observation 在同一条 text 里）"""
    def __init__(self):
        self._call = 0
        self.model_info: ModelInfo = {
            "vision": False, "function_calling": True, "json_output": False,
            "family": "mock", "structured_output": False, "multiple_system_messages": True,
        }

    async def create(self, messages, **kwargs) -> CreateResult:
        # ReAct 3 步：①查天气 ②发提醒 ③收工
        # 注意：mock 模式下 Action 和 Observation 都由 mock 返回（真实场景 Observation
        # 由工具执行器回填到 message history），按 call count 推进 state
        if self._call == 0:
            text = "Thought: 需要查北京天气\nAction: get_weather(city='北京')\nObservation: 有雨"
        elif self._call == 1:
            text = "Thought: 下雨了，提醒用户\nAction: send_reminder(content='带伞')\nObservation: 已加入日历"
        else:
            text = "Final Answer: 已提醒您带伞。"
        self._call += 1
        return CreateResult(
            content=text, finish_reason="stop",
            usage={"prompt_tokens": 20, "completion_tokens": len(text)}, cached=False,
        )
    async def close(self): pass


async def react_agent():

14.7 完整 Supervisor 实战（ch13↔ch14 对照）

14.7.1 完整 Supervisor 80 行

场景：Supervisor 委派任务给 3 个 Worker（Researcher / Writer / Editor），Worker 完成后回报 Supervisor，Supervisor 决定终止。


import asyncio
from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.conditions import MaxMessageTermination, TextMentionTermination
from autogen_core.models import CreateResult, ModelInfo


def make_mock_client(text: str):
    """工厂函数：每个 Agent 自己的 model_client（共享会乱套）"""
    class _MockClient:
        def __init__(self):
            self.model_info: ModelInfo = {
                "vision": False, "function_calling": False, "json_output": False,
                "family": "mock", "structured_output": False, "multiple_system_messages": True,
            }
        async def create(self, messages, **kwargs) -> CreateResult:
            return CreateResult(
                content=text, finish_reason="stop",
                usage={"prompt_tokens": 15, "completion_tokens": len(text)}, cached=False,
            )
        async def close(self): pass
    return _MockClient()


async def supervisor_team():
    supervisor = AssistantAgent(
        name="Supervisor",
        model_client=make_mock_client("请 Researcher 调研西湖历史。"),
        system_message="你是 Supervisor：把任务委派给 Worker，全部完成时说 DONE。",
    )
    researcher = AssistantAgent(
        name="Researcher",
        model_client=make_mock_client("西湖原为海湾，唐宋白居易、苏轼都留下足迹。"),
        system_message="你是研究员。",
    )
    writer = AssistantAgent(
        name="Writer",
        model_client=make_mock_client("西湖承载唐宋文脉，诗情画意。"),
        system_message="你是作家。",
    )
    editor = AssistantAgent(
        name="Editor",
        model_client=make_mock_client("DONE"),
        system_message="你是编辑，审稿后说 DONE。",
    )

    team = RoundRobinGroupChat(
        participants=[supervisor, researcher, writer, editor],
        # 委派顺序：supervisor → researcher → supervisor → writer → ... 简化版用 RoundRobin
        termination_condition=MaxMessageTermination(max_messages=8) | TextMentionTermination("DONE"),
    )

    result = await team.run(task="写一篇 100 字的西湖历史短文（3 步：调研-写作-审稿）")
    print(f"\n=== 共 {len(result.messages)} 条消息 ===\n")
    for i, m in enumerate(result.messages):
        print(f"[{i}] [{m.source}] {m.content[:80]}")


asyncio.run(supervisor_team())

14.8.5 5 大实战技巧（生产踩坑总结）

  1. 每个 Agent 一个 model_client 实例——共享会导致所有 Agent 返回相同 response
  2. description 比 system_message 更重要（SelectorGroupChat 选 speaker 全看它）——保持 20-50 字
  3. 真 LLM 跑不通时先 mock 验证——把 OpenAI 客户端换成 MockChatClient 排除 API 问题
  4. 用 asyncio.run() 包裹 team.run()——AutoGen 是 async 框架，忘了 await 不会报错（返回 coroutine）
  5. 生产加 tracing=True（在 Agent 创建时）—— 消息会通过 OpenTelemetry 导出，调试省一半时间

14.9 错误处理与终止（ch14 vs ch13 终止机制对照）

14.9.1 5 大错误类型

错误 触发条件 严重度 修复
Max Turn Exceeded LLM 调用次数 > max_turns 中 提高 max_turns / 简化任务
Function Call Failed 工具调用异常（参数错误 / 网络） 高 工具内 try-except + 返回错误信息
Speaker Loop A → B → A → B 无限循环 中 用 SelectorGroupChat + 强制 max_turns
Context Overflow messages 累积超过 LLM context 高 加 TokenUsageTermination + 滑动窗口

14.9.2 5 大错误修复示例


# 1. Termination Not Met → 加 MaxMessageTermination 兜底
team = RoundRobinGroupChat(
    participants=[...],
    termination_condition=(
        TextMentionTermination("DONE") |        # 主终止：显式 DONE
        MaxMessageTermination(max_messages=20)   # 兜底：20 条强制停
    ),
)

# 2. Max Turn Exceeded → 提高 max_turns
team = SelectorGroupChat(
    participants=[...],
    max_turns=30,  # 默认 12，改大
)

# 3. Function Call Failed → 工具内 try-except
def get_weather(city: str) -> str:
    try:
        return real_api_call(city)
    except Exception as e:
        return f"天气服务异常：{e}（请重试或换城市）"  # 错误信息回给 LLM，LLM 决定下一步

# 4. Speaker Loop → SelectorGroupChat + max_turns
team = SelectorGroupChat(
    participants=[A, B, C],
    termination_condition=MaxMessageTermination(max_messages=15),  # 强制 cap
)

# 5. Context Overflow → TokenUsageTermination + 滑动窗口
from autogen_agentchat.conditions import TokenUsageTermination
team = RoundRobinGroupChat(
    participants=[...],
    termination_condition=(
        TextMentionTermination("DONE") |
        TokenUsageTermination(max_total_token=8000)   # 累计 8K token 强制停
    ),
)
# 进一步：滑动窗口（v0.4 实验性 API，需配合 message_filter）

关键经验：生产必备 MaxMessageTermination | TokenUsageTermination 组合——避免"对话跑到天荒地老"或"token 烧爆"。

框架 成本倍数（vs 裸 API = 1x） 主要开销

14.11 小结 + 概念桥 + 22 术语速查

14.11.1 核心要点（5 条）

  1. AutoGen = 对话总线——所有 Agent 通过 GroupChat.messages 通信，GroupChatManager 选下一 speaker
  2. RoundRobinGroupChat 适合 90% 场景——固定角色轮转，简单可预测
  3. SelectorGroupChat 适合动态决策——LLM 看 history + description 选 speaker
  4. AutoGen 比 LangGraph 短 1.5-3x 代码——配置 Agent 即可，框架管状态/终止
  5. AutoGen 比 LangGraph 贵 1.5-1.7x token——消息累积 + Selector 多 1 次 LLM

14.11.2 ch14 怎么落到业务

场景 推荐
客服多分类路由 SelectorGroupChat + TextMentionTermination("DONE")
3 角色辩论 RoundRobinGroupChat + MaxMessageTermination(30)

快速原型（验证想法） AutoGen（最短代码）
