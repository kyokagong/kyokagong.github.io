20.1 引子：从 ch19 数据分析到 ch20 Browser-Use

ch19 把"信源可追溯"带给了数据场景——一张报表里的每个数字都能追到 SELECT … FROM … 与源表。ch20 要把"信源可追溯"扩展到浏览器场景——一次表单提交里的每个字段都能追到 (url, selector, extracted)。这不是"再加几个浏览器工具"，是引入视觉-操作闭环——Agent 不只看 DOM，还要操作 DOM。

核心论断：ch20 是 Part 4 的反向精简收官——只用 3 Agent + 6 工具完成浏览器自动化，比 ch19 的 5 Agent + 12 工具更简洁。Part 4 教会读者的不只是"怎么堆功能"，更是"怎么取舍"。

20.1.3 ch20 vs ch18/ch19 多 Agent 范式差异

  • ch18 = 调度型多 Agent（Supervisor 派活，Worker 互不通信）—— 适合"发散的搜索任务"
  • ch19 = 数据流型多 Agent（SQLAgent → ChartAgent 单向数据流）—— 适合"流水线的数据任务"

这是 Part 4 三联画：调度 → 数据流 → 操作，每种范式对应一种业务场景。

20.1.6 Part 4 三大多 Agent 共性提取（5 公理）

无论 ch18/19/20，三个项目的多 Agent 系统都遵守 5 公理：

  1. 公理 1 - 单一 Supervisor：必须有一个 Supervisor 决策中心，避免无主多 Agent
  1. 公理 2 - 消息隔离：Worker 之间默认不通信，需 Supervisor 路由
  1. 公理 3 - 终止二元条件：max_* + Verifier pass（资源 + 验收）
  1. 公理 4 - 操作可回滚：每个 Worker 操作必须可逆（SQL 事务 / snapshot / snapshot + back）
  1. 公理 5 - 安全层层叠加：每加一层 Worker，多一层安全风险（ch18 4 层 → ch19 5 层 → ch20 6 层）

公理化的价值：5 项目用同一套公理实现，避免每次重新设计多 Agent 架构。读者在面对新业务时，可以直接套这 5 公理。

20.1.7 Part 4 三联画的设计哲学：从"中心调度"到"操作型"

Part 4 后三个项目（ch18/ch19/ch20）的设计哲学演变：

  • ch18 = "怎么调度多个 Worker"：调度型，关注消息路由
  • ch19 = "怎么让 Worker 之间数据流动"：数据流型，关注单线传递
  • ch20 = "怎么让操作可回滚"：操作型，关注 sandbox 隔离

读者学完三章后，对"多 Agent"会有立体的理解——从"调度"到"数据流"到"操作"，层层递进。

20.2.3 终止条件设计

Supervisor 何时喊停？三个终止条件，任一满足即停：

20.3 30 行 Hello World：最小 Supervisor + BrowserAgent

20.3.1 supervisor.py（30 行最小骨架）


"""ch20 §20.3.1 — 最小 Supervisor + BrowserAgent (30 行骨架).
本节走 mock 模式：call_llm 返回固定 navigate 指令；
真实使用见 §20.4 6 工具 handlers（需要 pip install playwright）.
"""

from typing import Literal
from dataclasses import dataclass, field

@dataclass
class Task:
    user_request: str
    url: str = ""
    max_ops: int = 20

@dataclass
class WorkerOutput:
    action: Literal["navigate", "click", "type", "extract", "done"] = "done"
    selector: str = ""
    value: str = ""
    extracted: dict = field(default_factory=dict)

class BrowserWorker:
    """仅作 Worker 接口示意；真实实现见 tools.py."""

    def step(self, task: Task, history: list) -> WorkerOutput:
        _ = (task, history)
        return WorkerOutput(action="done")

class Supervisor:
    def __init__(self):
        self.browser = BrowserWorker()

    def run(self, task: Task):
        for i in range(task.max_ops):
            out = self.browser.step(task, history=[])
            if out.action == "done":
                return out.extracted
        return {}

if __name__ == "__main__":
    sup = Supervisor()
    result = sup.run(Task(user_request="Get GitHub stars"))
    print("result:", result)  # mock: {}

"""ch20 §20.4.2 — 6 工具 handlers (Playwright 真实调用).
真实运行：pip install playwright && playwright install chromium.
沙箱环境默认 mock 模式（DOMOp 返回固定值），真实浏览器需用户自装。
"""

import hashlib
from dataclasses import dataclass

@dataclass
class DOMOp:
    action: str
    selector: str = ""
    value: str = ""
    url: str = ""

class BrowserTools:
    """6 工具实现 — 接口签名与 §20.4.1 Schema 一一对应."""

    def navigate(self, op: DOMOp) -> dict:
        # 真实: await page.goto(op.url)
        return {"page_hash": hashlib.md5(op.url.encode()).hexdigest()[:8], "title": "Mock Page"}

    def click(self, op: DOMOp) -> dict:
        # 真实: await page.click(op.selector)
        return {"new_page_hash": hashlib.md5(op.selector.encode()).hexdigest()[:8]}

    def type_text(self, op: DOMOp) -> dict:
        # 真实: await page.fill(op.selector, op.value)
        return {"new_page_hash": hashlib.md5((op.selector+op.value).encode()).hexdigest()[:8]}

    def extract(self, op: DOMOp) -> dict:
        # 真实: await page.eval_on_selector_all(op.selector, "els => els.map(e => e.textContent)")
        return {"extracted": {"placeholder": f"text from {op.selector}"}}

    def screenshot(self, op: DOMOp) -> dict:
        # 真实: png_b64 = await page.screenshot()
        return {"base64_png": "<placeholder 1024 bytes>"}

    def download(self, op: DOMOp) -> dict:
        # 真实: async with page.expect_download() as dl: await page.goto(op.url)
        return {"file_hash": hashlib.md5(op.url.encode()).hexdigest()[:8]}

20.5.2 Supervisor 反向精简代码（vs ch19）


"""ch20 §20.5.2 — Supervisor 反向精简版.
对比 §19.5.6：ch19 Supervisor 注册 4 Worker，ch20 只注册 2 Worker.
"""

class SupervisorCh20:
    """ch20 Supervisor（3 Agent 精简版）."""

    def __init__(self):
        self.workers = {
            "browser": BrowserAgent(),
            "verifier": Verifier(),
        }

    def dispatch(self, subtask: str) -> str:
        if "validate" in subtask.lower():
            return self.workers["verifier"].validate(subtask)
        return self.workers["browser"].act(subtask)

    def should_terminate(self, ops_count: int, max_ops: int = 20) -> bool:
        return ops_count >= max_ops

20.5.4 Browser 任务反例：不引入 SQLAgent / ChartAgent

ch19 的 SQLAgent / ChartAgent 不适用于 Browser-Use 任务 —— 这些 Worker 处理"数据 → 图表"流水线，与 DOM 操作无关。如果硬塞，会得到：

  • SQLAgent：被错误触发，浪费一次 LLM 调用
  • ChartAgent：无图表输出，ChartPlot 走空

精简的依据：任务类型决定 Worker 数。Browser-Use 任务类型 ≤ 4 类，2 Worker 足够。

20.5.4a ch20 vs ch15 CrewAI 范式对比（横向参考）

ch20 是相对 ch19 反向精简（5 → 3 Worker），但绝对意义上 ch20 仍是 Supervisor + Worker 结构，与 ch15 的 Crew 平等结构不同。

Supervisor 派活信号目标 Worker调用
`task_kind="navigate"`BrowserAgentbrowser.navigate()
`task_kind="click"`BrowserAgentbrowser.click()
`task_kind="extract"`BrowserAgentbrowser.extract()
`task_kind="validate"`Verifierverifier.validate()

对比的本质：ch15 Crew 适合"4 个不同专长的角色互补"，ch20 适合"1 个主操作 + 1 个审核"。如果 Browser-Use 任务引入 Crew（如 BrowserAgent + ScreenShotAgent + FormFillerAgent + Auditor），会出现"LLM 调用翻倍但效果持平"的浪费 —— ch20 的精简避免了这一点。

20.5.4b §20.5 反向精简的本质：任务域宽度决定 Worker 数

任务域宽度 = Agent 需要处理的任务种类数。

  • ch19 数据分析任务域 = 6 类（提问 / 取数 / 分析 / 出图 / 解读 / 校对），需要 5 Worker
  • ch20 Browser-Use 任务域 = 4 类（导航 / 操作 / 抽取 / 校验），仅需 2 Worker

精简易错的判断准则："Worker 数 = 任务域宽度，而不是团队规模"。一个 5 人数据分析团队不必要 5 个 Worker，反之 1 人 Browser-Use 团队也不需要 1 个 Worker（真实 1 Worker 加 Supervisor 即可，但保留 1 个 Verifier 用于校验）。

20.5.5 终止条件扩展（vs ch19）

ch19 终止条件：max_loops=10 + max_tokens=250K + 任务完成信号。

ch20 终止条件：max_ops=20 + max_duration=5min + Verifier pass 信号。

max_loops=20 基于：ch18 max_loops=8 + ch20 Browser 任务单步成本更低（DOM 操作 < LLM 调用）+ 平均任务需要 6-12 步操作 + 留 50% buffer。生产环境可以根据页面复杂度调整：简单表单用 10，复杂审批流用 50。

@dataclass
class DOMLineage:
    url: str           # 来源 URL（血缘起点）
    selector: str      # CSS / XPath selector（血缘中间路径）
    extracted: dict    # 抽取出的结构化数据（血缘终点）

    def hash(self) -> str:
        return hashlib.md5(
            f"{self.url}|{self.selector}|{json.dumps(self.extracted, sort_keys=True)}".encode()
        ).hexdigest()[:16]

20.7.4a DOM 冲突检测


"""ch20 §20.7.4a — DOM 冲突检测 30 行."""

class DOMLineageGraph:
    def __init__(self):
        self.triples = []  # 存所有 DOMLineage

    def add(self, lineage: DOMLineage):
        """URL + selector 必须组合唯一."""
        for exist in self.triples:
            if exist.url == lineage.url and exist.selector == lineage.selector:
                if exist.hash() != lineage.hash():
                    return "CONFLICT"
        self.triples.append(lineage)
        return "OK"

    def trace_extract(self, extracted: dict):
        """追溯某抽取值来自哪个 DOM 节点."""
        for lin in self.triples:
            if lin.extracted == extracted:
                return lin
        return None

import re
import html

ALLOWED_DOMAINS = ["github.com", "shop.com", "arxiv.org"]  # L1

class SafetyGuard:
    def __init__(self):
        self.ops_count = 0
        self.audit_log = []  # L2

    def check_url(self, url: str) -> bool:
        domain = url.split("/")[2] if "://" in url else ""
        allowed = domain in ALLOWED_DOMAINS  # L1
        self.audit_log.append(("url_check", url, allowed))  # L2
        return allowed

    def check_op(self, op: str) -> bool:
        self.ops_count += 1
        return self.ops_count <= 20  # L4

    def rollback(self, snapshot_hash: str) -> bool:
        """L3: Browser 天然支持 — page.go_back() 或恢复 DOM 快照."""
        return bool(snapshot_hash)

    def sanitize_extract(self, raw: dict) -> dict:
        """L6: 抽取结果 sanitize 防 XSS."""
        return {k: html.escape(str(v)) for k, v in raw.items()}

    def check_csrf(self, headers: dict) -> bool:
        """L6: 提交前校验 CSRF token."""
        return "x-csrf-token" in headers
