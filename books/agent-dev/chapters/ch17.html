17.1.3 单 Agent 安全护栏原则

代码助手和个人助理的最大区别是 风险等级：

17.3.1a ch07 三协议在 ch17 8 工具上的应用

ch07 §7.4 对比了 OpenAI / Anthropic / Google 三种 Function Calling 协议，ch17 8 个工具的 Schema 必须严格匹配所选协议——选错协议会导致所有工具调用失败。

工具OpenAI tools 字段Anthropic tools 字段Google tools 字段
ls / find / greptools: [{type:"function", function:{name, description, parameters}}]tools: [{name, description, input_schema}]tools: [{functionDeclarations: [{name, description, parameters}]}]
test / run同上 + strict: true同上 + 自动 parallel tool calls同上 + parameters.required 必填
lint / format同上 + 在 description 里强调 dry-run同上 + description 必须含 Caution 关键字同上

ch17 默认协议选型：OpenAI 协议。理由：

  1. 生态最大：Cursor / Continue / Cody 等 IDE 都原生支持 OpenAI 协议
  2. 第三方库最全：LangChain / LlamaIndex / OpenAI Agents SDK 都围绕 OpenAI 协议
  3. 文档完整：OpenAI Cookbook 有完整 examples

如果读者硬要用 Anthropic SDK 或 Google Gemini，只需替换 Schema 字段名（parameters → input_schema），handler 逻辑完全不变。

17.3.1b 7 字段必须填的强制约束

无论选哪个协议，ch17 的 JSON Schema 都必须严格定义：

#字段原因ch17 处理
1name 工具名LLM 必须知道调用哪个全部 snake_case
2descriptionLLM 决定何时调全部 50-200 字
3parameters.typeJSON Schema 必备全部 "object"
4properties.<field>.type参数类型全部 string/integer/boolean/enum
5properties.<field>.descriptionLLM 知道怎么填全部 30-100 字
6required哪些参数必须ch17 全部至少 1 个
7（OpenAI 专属）strict: true严格 schema 验证全部开启

反例（缺 6/7 字段，导致 LLM 调用失败）：

{"name": "ls", "description": "列文件"}

正例（ch17 风格）：

{"name":"ls","description":"列出目录文件...","strict":true,
 "parameters":{"type":"object","properties":{
   "path":{"type":"string","description":"项目内相对路径"}},
   "required":["path"]}}

import json, subprocess

TOOLS = {
    "ls":   {"params": ["path"], "handler": lambda p: subprocess.run(["ls", p], capture_output=True, text=True).stdout},
    "find": {"params": ["name"], "handler": lambda n: subprocess.run(["find", ".", "-name", n], capture_output=True, text=True).stdout},
    "grep": {"params": ["pattern", "path"], "handler": lambda p, d: subprocess.run(["grep", "-rn", p, d], capture_output=True, text=True).stdout},
    "git_status": {"params": [], "handler": lambda: subprocess.run(["git", "status", "--short"], capture_output=True, text=True).stdout},
}

def call_tool(name, args):
    return TOOLS[name]["handler"](*args)

17.4.1 ls / find / grep handler（只读组）

def handle_ls(path: str) -> str:
    """列出 path 下文件（不含隐藏）。path 必须在项目根内。"""
    safe = _safe_path(path)
    out = subprocess.run(["ls", "-la", safe], capture_output=True, text=True, timeout=5)
    return out.stdout or "(空目录)"

def handle_find(name: str, path: str = ".") -> str:
    """按文件名搜索，path 必须在项目根内。"""
    safe = _safe_path(path)
    out = subprocess.run(
        ["find", safe, "-name", name, "-not", "-path", "*/node_modules/*", "-not", "-path", "*/.git/*"],
        capture_output=True, text=True, timeout=10
    )
    return out.stdout[:5000] or "(未找到)"

def handle_grep(pattern: str, path: str = ".", file_glob: str = "*") -> str:
    """正则搜索文件内容。"""
    safe = _safe_path(path)
    out = subprocess.run(
        ["grep", "-rn", "--include=" + file_glob, pattern, safe],
        capture_output=True, text=True, timeout=15
    )
    return out.stdout[:8000] or "(未找到)"

17.4.2 git status / diff / log handler（只读组）

def handle_git_status() -> str:
    """查看工作区变更（短格式）。"""
    out = subprocess.run(["git", "status", "--short"], capture_output=True, text=True, timeout=5)
    return out.stdout or "(无变更)"

def handle_git_diff(file: str = "") -> str:
    """查看变更详情。可选 file 过滤单个文件。"""
    args = ["git", "diff"]
    if file: args.append(file)
    out = subprocess.run(args, capture_output=True, text=True, timeout=10)
    return out.stdout[:10000] or "(无 diff)"

def handle_git_log(n: int = 10) -> str:
    """查看最近 n 个 commit。"""
    out = subprocess.run(
        ["git", "log", "--oneline", f"-{n}"],
        capture_output=True, text=True, timeout=5
    )
    return out.stdout or "(无历史)"

17.4.3 test / run handler（副作用组）

def handle_test(cmd: str, cwd: str = ".") -> str:
    """跑测试。cmd 必须是 pytest 或 npm test，禁止其他。"""
    if cmd not in ("pytest", "npm test", "yarn test", "pnpm test"):
        return "❌ 非法测试命令，仅允许 pytest / npm test / yarn test / pnpm test"
    safe = _safe_path(cwd)
    out = subprocess.run(cmd.split() + ["--tb=short"], capture_output=True, text=True,
                       timeout=120, cwd=safe)
    return f"=== STDOUT ===\n{out.stdout[-3000:]}\n=== STDERR ===\n{out.stderr[-1500:]}"

def handle_run(cmd: str) -> str:
    """⚠️ 高危！执行任意 shell 命令。需要 _ALLOW_WRITE=True。"""
    if not _ALLOW_WRITE:
        return "❌ 默认只读模式。要执行写操作请先 ALLOW_WRITE=True"
    if any(bad in cmd for bad in _BLACKLIST):
        return f"❌ 黑名单命令被拦截：{cmd[:50]}"
    out = subprocess.run(cmd, shell=True, capture_output=True, text=True, timeout=60)
    _audit(cmd, out.returncode)
    return out.stdout[-3000:] or out.stderr[-1500:]

注：所有 _ALLOW_WRITE=True 通过的 run/format 调用，都会调 _audit()（在 §17.5.2）记录到 audit.log。该文件必须 git tracked，便于事后审计。

17.4.4 lint / format handler（写操作组）

def handle_lint(cmd: str = "ruff check .") -> str:
    """代码静态检查（默认 ruff）。"""
    if cmd not in ("ruff check .", "flake8 .", "eslint .", "pylint ."):
        return "❌ 非法 lint 命令"
    out = subprocess.run(cmd.split(), capture_output=True, text=True, timeout=60)
    return out.stdout[-3000:] or out.stderr[-1500:] or "✅ lint 通过"

def handle_format(cmd: str = "ruff format .", dry_run: bool = True) -> str:
    """⚠️ 写操作！代码格式化。默认 dry_run=True 仅显示差异。"""
    if dry_run:
        out = subprocess.run(cmd.split() + ["--check", "--diff"],
                            capture_output=True, text=True, timeout=60)
        return f"=== DIFF ===\n{out.stdout[-3000:]}" if out.stdout else "✅ 已格式化"
    if not _ALLOW_WRITE:
        return "❌ 默认只读。要真格式化请 ALLOW_WRITE=True 且 dry_run=False"
    out = subprocess.run(cmd.split(), capture_output=True, text=True, timeout=120)
    _audit(cmd, out.returncode)
    return "✅ 已格式化" if out.returncode == 0 else out.stderr[-1500:]
handler 设计要点：所有 handler 都返回 字符串（不是 Python 对象），便于 LLM 直接读。

17.5.2 tools.py 完整代码（节选）

# tools.py — 8 工具 + 安全护栏
import subprocess, os, json
from datetime import datetime
from pathlib import Path

PROJECT_ROOT = Path(__file__).parent.resolve()
_ALLOW_WRITE = False
_BLACKLIST = ["rm -rf /", "sudo ", "git push --force", ":(){ :|:& };:", "mkfs", "dd if="]
_audit_log = PROJECT_ROOT / "audit.log"

def _safe_path(p: str) -> str:
    """解析并校验 path 在项目根内。"""
    abs_path = (PROJECT_ROOT / p).resolve()
    if not str(abs_path).startswith(str(PROJECT_ROOT)):
        raise ValueError(f"❌ 路径逃逸：{p} 不在项目根 {PROJECT_ROOT}")
    return str(abs_path)

def _audit(cmd: str, rc: int) -> None:
    """记录所有写操作到 audit.log。"""
    ts = datetime.now().isoformat()
    with open(_audit_log, "a") as f:
        f.write(f"{ts}\t{cmd}\trc={rc}\n")

# 8 handler（同 17.4 节，省略）
HANDLERS = {
    "ls": handle_ls, "find": handle_find, "grep": handle_grep,
    "git_status": handle_git_status, "git_diff": handle_git_diff,
    "git_log": handle_git_log,
    "test": handle_test, "run": handle_run,
    "lint": handle_lint, "format": handle_format,
}

17.5.3 agent.py 主循环

# agent.py — ReAct 主循环（ch10 §10.6）
import json
from openai import OpenAI
from tools import HANDLERS

class CodeAssistantAgent:
    def __init__(self, llm=None):
        self.llm = llm or OpenAI()
        self.history = []  # 短期记忆（ch08 §8.2）

    def run(self, query: str) -> str:
        self.history.append({"role": "user", "content": query})
        for step in range(10):  # 最多 10 步
            resp = self.llm.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{"role": "system", "content": SYS_PROMPT}] + self.history,
                tools=TOOLS_SCHEMA,
            )
            msg = resp.choices[0].message
            if msg.tool_calls:
                for tc in msg.tool_calls:
                    args = json.loads(tc.function.arguments)
                    result = HANDLERS[tc.function.name](**args)
                    self.history.append({"role": "tool", "tool_call_id": tc.id,
                                        "content": result})
                self.history.append(msg)
                continue
            return msg.content
        return "⏱ 超过 10 步未完成"

from pathlib import Path

class ProjectMemory:
    def __init__(self, project_root: str):
        self.short_term = []
        self.db = sqlite3.connect(Path(project_root) / "ch17_memory.db")
        self.db.execute("""CREATE TABLE IF NOT EXISTS prefs (
            key TEXT PRIMARY KEY, value TEXT)""")
        # 简化向量层：mock embedding
        self.vectors = {}  # {code_id: (vector, code_text)}

    def remember_pref(self, key, value):
        self.db.execute("INSERT OR REPLACE INTO prefs VALUES (?,?)", (key, value))
        self.db.commit()

    def get_pref(self, key, default=None):
        cur = self.db.execute("SELECT value FROM prefs WHERE key=?", (key,))
        row = cur.fetchone()
        return row[0] if row else default

    def index_code(self, code_id: str, code_text: str):
        """向量层：mock embedding（实际应用用 sentence-transformers）"""
        # 简化：hash 作为"embedding"
        vec = np.array([hash(code_text[:100]) % 1000 / 1000.0] * 64)
        self.vectors[code_id] = (vec, code_text)

    def search_code(self, query: str, top_k: int = 3) -> list:
        """语义搜索代码片段（mock）"""
        results = []
        for code_id, (vec, text) in self.vectors.items():
            score = float(np.dot(vec, vec))  # mock 评分
            results.append((score, code_id, text[:200]))
        results.sort(reverse=True)
        return results[:top_k]

17.7 安全护栏：read-only 默认 + 写操作确认

17.7.1 read-only 默认

ch17 有 3 类操作：

操作类型工具默认行为
🟢 只读ls / find / grep / git_status / git_diff / git_log永远允许（无需 ALLOW_WRITE）
🟡 副作用可控test / lint永远允许（只产生缓存或报告）
🔴 写操作run / format / git commit / git push必须 ALLOW_WRITE=True

设计哲学：deny-by-default。所有写操作默认拒绝，用户显式开启。这是 fail-safe 的工程实践——bug 默认行为应该是"什么也不做"，不是"删除一切"。

17.7.2 5 类危险命令拦截（_BLACKLIST）

_BLACKLIST = [
    "rm -rf /",           # 删根目录
    "rm -rf ~",           # 删家目录
    "sudo ",              # 提权（Code Assistant 不应需要）
    "git push --force",   # 覆盖远程历史
    "git push -f",        # 同上简写
    ":(){ :|:& };:",      # fork 炸弹
    "mkfs",               # 格式化文件系统
    "dd if=",             # 块设备写
    "chmod -R 777 /",     # 全权限
    "curl ... | sh",      # 远程脚本执行
]

任何包含以上子串的 run 或 format 命令被立即拒绝，返回字符串错误而非执行。

17.7.3 Audit log

所有"过了白名单又过了黑名单"的写操作都要记录：

def _audit(cmd: str, rc: int) -> None:

    with open(_audit_log, "a") as f:

17.10.4 ch18 多 Agent 完整升级代码

注：WriterAgent / ReviewerAgent 将在 ch18 §18.5 多 Agent 拆分 中定义——ch17 §17.10.4 仅展示 supervisor 顶层结构，便于读者理解 ch17 → ch18 的接口边界。

ch17 单 Agent → ch18 多 Agent 不是替换，是 包装一层 supervisor：

# ch18 supervisor.py（在 ch17 基础上）
from ch17 import CodeAssistantAgent, HANDLERS

class ResearchSupervisor:
    """ch18 升级：把 ch17 包成 researcher 子 Agent，加 writer + reviewer"""

    def __init__(self):
        # ch17 Agent 不动，仅加 2 工具（arxiv_search / web_search）
        self.researcher = CodeAssistantAgent(
            extra_tools={
                "arxiv_search": handle_arxiv_search,
                "web_search": handle_web_search,
            }
        )
        self.writer = WriterAgent(model="claude-3-5-sonnet")
        self.reviewer = ReviewerAgent(rubric="ch18-academic-rubric")

    def run(self, query: str) -> str:
        # Step 1: ch17 风格单 Agent 研究（只读 + shell）
        research_notes = self.researcher.run(f"调研 {query}，输出 5 个关键点")
        # Step 2: writer 基于研究写综述
        draft = self.writer.run(f"基于以下研究笔记，写综述：\n{research_notes}")
        # Step 3: reviewer 检查引用 + 准确性
        review = self.reviewer.run(f"检查以下综述：\n{draft}")
        return f"=== 研究 ===\n{research_notes}\n=== 综述 ===\n{draft}\n=== 评审 ===\n{review}"

核心思想：ch17 是 ch18 的 researcher 子 Agent——ch18 多 Agent 架构 = ch17（升级 2 工具） + 2 个新 Agent + supervisor 包装。读者读完 ch17 即可平滑升级到 ch18。
