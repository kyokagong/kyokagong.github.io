24.1 引子——为什么 Agent 比 LLM 贵 10 倍

24.1.1 一句话反差

ch23 留了一句反直觉的真相:"防御每多一层,token 就多一份。" 这句话在安全语境里是必要的妥协,但在财务语境里就是直接的成本曲线——每一道防线都让一次调用的账单变长。本章要回答的不是"要不要安全",而是"在安全前提不变的情况下,如何让每一次调用的 token 数降到合理区间"。

如果 ch23 是 Agent 的"免疫系统",本章就是 Agent 的"会计系统"——免疫要花钱,会计决定花多少、花在哪、谁该付钱。

24.1.2 ch23 → ch24 桥接

24.2 Token 经济学基础

24.2.1 token 计费规则

关键规则:

  • input token 和 output token 价格不同——output 通常是 input 的 3-5 倍(因为 output 是生成的,生成成本高于阅读)
  • 不同模型价格差异 100×——GPT-5 与 GPT-4o-mini 差 30 倍,与 Llama-3-8B-self-hosted 差 100 倍
  • context window 与成本非线性——32k context 的模型比 8k 贵 2×,但处理能力不是 4×

模型 Input ($/M token) Output ($/M token) Context 适合场景
GPT-5 $5 $15 200k 复杂推理 / 多步规划
Claude 4.5 Sonnet $3 $15 200k 长文档 / 代码
Gemini 2.5 Pro $2.5 $10 1M 大 context / 多模态
GPT-4o-mini $0.15 $0.6 128k 简单任务 / 路由
DeepSeek V3 $0.27 $1.1 64k 中文 / 性价比
Llama-4-70B(self-hosted) $0.10 $0.10 128k 高频 / 隐私
Llama-3-8B(self-hosted) $0.02 $0.02 8k 大量简单任务

(数据基于 2026 年 H1 公开定价,实际以官方为准;价格为 input/output USD / 1M tokens)

24.2.2 真实账单示例

场景:某客服 Agent 处理 1 个工单,平均 10 轮 LLM 调用。

步骤 输入 token 输出 token 模型 单次成本
1. 理解工单 500 100 GPT-4o-mini $0.0001
2. 检索知识库 2000 200 GPT-4o-mini $0.0004
3. 工具调用查订单 800 50 GPT-4o-mini $0.0001
4. 生成回复 1500 300 GPT-5 $0.0122
... (6 步重复)... $0.020
单工单合计 $0.030

每日 1000 工单 → 日 $30,月 $900。如果全用 GPT-5:日 $150,月 $4500(5 倍)。

24.2.3 context window 与成本非线性

32k context 不只是"能装更多",而是:

  • 模型权重差异:GPT-5-32k 训练成本高
  • 推理 GPU 占用差异:32k context 占用更多 KV cache
  • 延迟增加:长 context 推理时间呈 O(n²) 增长

经验法则:能用 8k 解决的问题,绝不用 32k。能用 32k 解决的,绝不用 200k。

24.2.4 4 大隐藏成本因子

因子 含义 典型占比
重试成本 LLM 调用失败重试 3-5 次 5-15%
超时浪费 5 分钟超时任务在 4 分 59 秒才返回 3-8%
流式输出 output token 即使被截断也按完整 token 计费 2-5%
重复 system prompt 每次调用都带相同 system prompt 10-25%

24.2.5 token 估算速算

经验法则:1 个汉字 ≈ 1.5 个 token(中文)/ 1 个英文单词 ≈ 1.3 个 token(英文)。

内容 字符 估算 token
1 段邮件(200 字) 200 300
1 篇文章(3000 字) 3000 4500
1 本书(10 万字) 100000 150000
1 轮多轮对话(平均 5 轮) 5000 7500

实战技巧:调 LLM 前先 len(text) 1.5 估算 token,再 × 单价 = 预估成本。这能在开发阶段就发现"为啥这条 prompt 这么贵"。

24.3.3 mock 路由器实现

# 4 级路由器 mock(伪 LLM)


def route(task_complexity: int, has_sensitive: bool, user_preference: str) -> str:
    """根据任务复杂度路由到合适模型"""
    if has_sensitive:
        return "human_escalation"
    if user_preference == "gpt-5":
        return "gpt-5"
    if task_complexity <= 2:
        return "llama-3-8b-self-hosted"
    elif task_complexity <= 5:
        return "gpt-4o-mini"
    else:
        return "gpt-5"

    ("写调研报告", 8, False, "default"),  # → gpt-5

24.3.4 路由的隐藏成本

路由器本身不是免费的:

  • 路由器判断需要 1 次小模型调用(~$0.0001)
  • 路由错误会导致任务失败 → 重试 → 2× 成本
  • 正确率要 > 95% 才能省钱,否则不如直接用中端模型

24.3.5 路由策略演进

阶段 策略 实现 适用
v1 关键词路由 if "天气" in query: L1 早期
v2 复杂度评分路由 用 LLM 评 1-10 分 中期
v3 路由器模型 用 BERT/小模型专门训练路由 成熟期
v4 自我评估路由 Agent 自我报告复杂度 高级

v3 路由器模型最稳定:用历史数据训练一个分类器,输入 query,输出 4 个模型的概率分布。

24.3.6 路由失败的代价

失败类型 后果 频率
下溢(路由给太便宜的模型) 输出质量低,用户投诉 5-15%
上溢(路由给太贵的模型) 成本浪费 10-25%
重复路由(路由器自己也循环) token 翻倍 < 1%

关键指标:下溢率 < 5% 才能保证用户体验,上溢率 < 15% 才能保证成本优势。

def ab_test_router(strategy_a_cost: float, strategy_b_cost: float,

24.4 缓存策略——同一问题不调用两次

24.4.2 语义缓存实现

import hashlib



class SemanticCache:
    """语义缓存(精确 + embedding 占位)"""
    def __init__(self):
        self.cache = {}  # {hash: response}





    def _key(self, query: str) -> str:
        # 简化版:实际应该用 embedding + cosine 相似度
        normalized = query.lower().strip()
        return hashlib.md5(normalized.encode()).hexdigest()





    def get(self, query: str):
        return self.cache.get(self._key(query))





    def set(self, query: str, response: str):
        self.cache[self._key(query)] = response




实测



cache = SemanticCache()
queries = ["查天气", "查询天气", "今天天气如何", "写邮件"]
for q in queries:
    if cache.get(q):
        print(f"  命中缓存: {q}")
    else:
        cache.set(q, f"response-{q}")
        print(f"  缓存新查询: {q}")

实测输出:4 次调用,2 次缓存命中(50%)

24.4.4 缓存命中率优化

命中率 节省成本 优化策略
< 20% < 20% 检查 query 标准化(小写/去标点)
20-50% 20-40% 加语义缓存(GPT-4o-mini 做 embedding)
50-80% 40-60% 加 prompt cache + 复用 system prompt
> 80% 60-80% 警惕:缓存可能掩盖真实问题

24.4.5 缓存失效策略

策略 含义 适用
TTL 缓存 5 分钟后失效 时间敏感(天气/股价)
版本号 prompt 变更时清空缓存 prompt 频繁更新
主动刷新 后台 cron 每小时刷新热点 key 高频查询
LRU 最近最少使用淘汰 内存有限

24.4.6 缓存的隐藏陷阱

  • 缓存污染:恶意 query 命中缓存后,所有用户都收到相同恶意回复
  • 缓存过期不一致:不同节点 TTL 不一致,导致用户体验波动
  • 缓存击穿:热点 key 过期瞬间,大量请求穿透到 LLM

解决方案:缓存 key 加租户隔离 + TTL 加 jitter + 热点 key 后台异步刷新。

24.4.7 缓存命中率监控

class CacheMonitor:


    """缓存命中率监控"""
    def __init__(self):
        self.hits = 0
        self.misses = 0





    def record_hit(self):
        self.hits += 1





    def record_miss(self):
        self.misses += 1





    def hit_rate(self) -> float:
        total = self.hits + self.misses
        return self.hits / total if total > 0 else 0





    def report(self):
        rate = self.hit_rate()
        status = "🟢 优秀" if rate > 0.5 else "🟡 良好" if rate > 0.3 else "🔴 需优化"
        print(f"命中率: {rate:.1%} ({self.hits}/{self.hits + self.misses}) {status}")




实测



monitor = CacheMonitor()
for i in range(100):
    if i % 3 == 0:  # 33% 命中
        monitor.record_hit()
    else:
        monitor.record_miss()
monitor.report()



输出:命中率: 33.3% (33/100) 🟡 良好

24.5.2 滑动窗口 + 摘要压缩实现

class ContextCompressor:


    """简单上下文压缩器(滑动窗口 + 摘要)"""
    def __init__(self, max_turns=5, summary_target=100):
        self.turns = []
        self.max_turns = max_turns
        self.summary_target = summary_target





    def add(self, role: str, content: str):
        self.turns.append({"role": role, "content": content})
        if len(self.turns) > self.max_turns:
            # 触发摘要:把前半段压缩
            self._summarize_old()





    def _summarize_old(self):
        # mock:实际调用 LLM
        old_turns = self.turns[:len(self.turns) - self.max_turns]
        summary = f"[摘要]:{len(old_turns)} 轮对话,主要话题为 {old_turns[0]['content'][:20]}"
        # 替换前半段
        self.turns = [{"role": "system", "content": summary}] + self.turns[-self.max_turns:]





    def get_context(self):
        return self.turns




实测



comp = ContextCompressor(max_turns=3)
for i in range(10):
    comp.add("user", f"问题 {i}: 今天天气怎么样?")
    comp.add("assistant", f"回答 {i}: 晴天")
print(f"压缩后轮数: {len(comp.get_context())}")



输出:压缩后轮数: 4 (1 摘要 + 3 最近)

24.6.2 mock 工具配额管理

class ToolBudget:


    """工具配额管理(mock)"""
    def __init__(self):
        self.limits = {
            "web_search": {"per_minute": 10, "per_day": 1000, "cost": 0.005},
            "database": {"per_minute": 60, "per_day": 5000, "cost": 0.0001},
            "code_exec": {"per_minute": 5, "per_day": 200, "cost": 0.01},
        }
        self.usage = {tool: {"minute": 0, "day": 0} for tool in self.limits}





    def call(self, tool: str) -> bool:
        limit = self.limits[tool]
        usage = self.usage[tool]
        if usage["minute"] >= limit["per_minute"]:
            print(f"  ❌ {tool} 分钟配额耗尽")
            return False
        if usage["day"] >= limit["per_day"]:
            print(f"  ❌ {tool} 日配额耗尽")
            return False
        usage["minute"] += 1
        usage["day"] += 1
        print(f"  ✅ {tool} 调用成功 (cost ${limit['cost']})")
        return True

class CostQuota:


    """成本配额(mock)"""
    def __init__(self):
        self.quotas = {
            "team-a": {"daily_budget": 100, "monthly_budget": 2500},
            "team-b": {"daily_budget": 50, "monthly_budget": 1200},
        }
        self.usage = {team: {"daily": 0, "monthly": 0} for team in self.quotas}





    def check(self, team: str, cost: float) -> bool:
        quota = self.quotas[team]
        usage = self.usage[team]
        if usage["daily"] + cost > quota["daily_budget"]:
            print(f"  ⚠️ {team} 日配额即将耗尽")
            return False
        if usage["monthly"] + cost > quota["monthly_budget"]:
            print(f"  ❌ {team} 月配额耗尽")
            return False
        usage["daily"] += cost
        usage["monthly"] += cost
        return True

print(f"team-a 50 calls: {quota.check('team-a', 50)}")  # True

24.8.6 计费 code 解耦

# billing.py —— 成本计算单独模块(实际项目建议命名 billing.py,避免与未来包冲突)


class CostCalculator:
    PRICES = {
        "gpt-5": (5, 15),
        "gpt-4o-mini": (0.15, 0.6),
    }





    @classmethod
    def calc(cls, model: str, in_tok: int, out_tok: int) -> float:
        in_price, out_price = cls.PRICES[model]
        return in_tok  in_price / 1e6 + out_tok  out_price / 1e6




agent.py —— 业务代码调用成本模块


from billing import CostCalculator


cost = CostCalculator.calc("gpt-5", 1500, 300)

好处:模型价格变动时,只需改 cost.py 一处;支持 A/B 测试不同价格;便于 unit test。

24.9.2 mock 成本 trace

class CostTrace:


    """成本 trace(mock)"""
    PRICES = {
        "gpt-5": (5, 15),  # (input, output) per M token
        "gpt-4o-mini": (0.15, 0.6),
        "llama-3-8b": (0.02, 0.02),
        "llama-guard-1b": (0.10, 0.10),
    }





    def __init__(self, task_id: str):
        self.task_id = task_id
        self.spans = []





    def add_span(self, name: str, model: str, in_tok: int, out_tok: int):
        in_price, out_price = self.PRICES[model]
        cost = in_tok  in_price / 1e6 + out_tok * out_price / 1e6
        self.spans.append({"name": name, "model": model, "in": in_tok, "out": out_tok, "cost": cost})





    def total(self):
        return sum(s["cost"] for s in self.spans)





    def report(self):
        print(f"Task {self.task_id}:")
        for s in self.spans:
            print(f"  {s['name']:20s} ({s['model']:15s}): ${s['cost']:.4f}")
        print(f"  Total: ${self.total():.4f}")
