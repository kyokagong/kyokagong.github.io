28.1.2 三层认知边界

我们要先界定三个常被混用的概念——LLM、Agent、AGI——之间的关系,才能看清 Agent 在这条路上扮演什么角色:

28.3 Agent / LLM / AGI 三者的关系

28.3.1 概念辨析

概念定义类比主要研究问题
LLM大语言模型,通过预测下一 token 训练的神经网络大脑皮层(无手无脚)推理、对齐、长上下文、推理效率
Agent以 LLM 为大脑,具备工具调用、记忆、规划能力的系统完整的人(大脑 + 手 + 记忆)任务规划、工具使用、错误恢复
AGI通用人工智能,具备人类水平或超越人类的广泛认知能力完整的人 + 自我意识价值对齐、持续学习、跨领域泛化

28.3.2 三层递进关系

LLM ──(大脑)──> Agent ──(具身化)──> AGI

   ↑                ↑                  ↑


预测 token      调用工具 / 规划       价值对齐 / 自我驱动
    1. LLM 是基础层,没有 LLM 就没有现代 Agent;
    2. Agent 是应用层,LLM 的能力通过 Agent 才能在真实世界落地;
    3. AGI 是目标层,Agent 是当前最现实的演进路径,但 AGI 还需要突破价值对齐、长期目标、跨域迁移等 LLM 与 Agent 都没解决的问题。

28.3.3 Agent 在 AGI 路径上的不可替代性

维度纯 LLM 路线Agent 路线
与世界交互❌ 只能输出文本✅ 调用工具、操作 GUI、读写文件
持续学习❌ 权重冻结(后训练除外)✅ 通过工具 / 记忆持续学习
长时任务❌ 受上下文窗口限制✅ 通过压缩 / 摘要 / 外部记忆延续
价值对齐⚠️ 主要在训练阶段✅ 可在工具调用层加策略门
这就是为什么 AGI 几乎一定要经过 Agent 这一阶段:Agent 是 LLM 与世界之间的接口,没有这个接口,LLM 再强也只是"很会说话的人",而不是"能做事的人"。

28.4 短期路线(2026-2028)

28.4.1 三个具体里程碑

里程碑时间窗标志主要瓶颈
单 Agent 工业化2026-2027评测、安全、成本三角成熟;每个企业有标准化 Agent 平台数据治理、权限矩阵、合规
垂直多 Agent 普及2027-2028软件开发 / 研究 / 客服等领域出现事实标准任务路由、可观测性、Case routing
企业 Agent 规模化2027-2028Fortune 500 中 30-50% 业务线有 Agent组织变革、ROI 证明、监管
以上里程碑为公开报告(McKinsey、Stanford AI Index 等)行业估计,非企业个体数据;落地时按业务线 ROI 调整。

28.4.2 短期重点

  1. 评测体系成熟:从"看着不错"到"可比较、可回归、可发布";
  2. 安全防御标准化:5 层防御栈成为行业共识;
  3. 成本控制常态化:每千次任务成本成为选型硬指标;
  4. 企业落地路径清晰:从 PoC 到生产 6 阶梯成为通用话术。

28.4.3 短期不会发生的事

    1. ❌ AGI 不会到来(即使乐观派也几乎不会在 2028 前宣称 AGI);
    2. ❌ Agent 不会替代程序员(只会改变程序员的工作方式);
    3. ❌ 监管不会全面落地(主要框架仍在演进,执法尚需时日)。

28.5 中期路线(2028-2030)

28.5.1 三个关键突破

突破描述影响
自进化 AgentAgent 能从经验中学习并改写自己的策略减少人工调优;但需要严格的回放与隔离机制
长时记忆工程化Agent 能跨任务、跨周、跨月记忆关键经验个性化 Agent 真正可用;但隐私与遗忘机制需完善
人机协作常态化人类与 Agent 形成稳定的工作流(类似现在的 IDE 与程序员的协作)改变几乎所有知识工作

28.5.2 中期主线

    1. Agent 经济雏形:Agent 之间能形成稳定的协议、市场、结算;
    2. 价值对齐工程化:从"训练阶段对齐"扩展到"运行阶段对齐";
    3. 跨模态常态化:语音 / 图像 / 视频 / 3D 与 Agent 深度集成。

28.5.3 中期可能遇到的天花板

    1. 上下文天花板:即使加到 1M token,长程规划仍然困难;
    2. 算力天花板:自进化 Agent 需要大量算力做回放与评估;
    3. 组织天花板:不是技术不行,而是组织跟不上。
28.5.3 这条提示与 ch27 §27.1 三道墙呼应——中期遇到的瓶颈,大概率不是技术,而是组织。

28.6 长期路线(2030+)

28.6.1 三个开放问题

问题描述当前主流观点
AGI 是否可达现有架构(Transformer)能否延展到 AGI学界分歧大,无共识

28.6.2 三种长期情景(注:均为学者预测,非断言)

情景概率(主观)描述
AGI 渐进派中通过 Agent + 长时记忆 + 自进化逐步逼近 AGI
架构突破派低需要新的训练范式(非 Transformer)才能达成 AGI
AGI 不可能派少数现有物理 / 信息架构无法支撑 AGI
情景概率为本书作者主观估计,基于公开文献(GPT-4 / Claude / Gemini 等模型趋势报告)与个人判断,非任何机构正式预测;读者应按自身风险偏好决定是否将本书路线图作为决策依据。

28.6.3 长期主线

    1. AI 治理成熟:EU AI Act / NIST AI RMF / ISO/IEC 42001 落地为强制标准;
    2. 人机分工清晰:人类保留价值判断、创造性、责任;Agent 承担重复、大规模、长时任务;
    3. Agent 成为基础设施:像今天的数据库、容器一样成为默认组件。
本节不含具体年份预测。AGI 时间表属于日期敏感且有争议的领域;读者应参考最新公开报告,不要把任何路线图当作承诺。

28.7 Agent 与人类智能分工

28.7.1 人类保留的能力

能力描述
价值判断"这件事应不应该做"——决定目标与边界
创造"应该做什么"——提出新的产品 / 体验 / 想法
责任"做错了谁负责"——承担决策的最终后果
跨域迁移"这件事跟另一件事有什么相似"——在陌生情境下找到路径
情感与共情"对方需要什么"——理解他人的处境

28.7.2 Agent 擅长的能力

能力描述
重复执行"做这件事 1000 次,每次都一样"
大规模检索"从 100 万条记录里找符合 X 的"
长时记忆"5 年前的今天我跟你说过什么"
24×7 不疲劳"半夜三点也要有人接电话"
多任务并行"同时盯 10 个不同的数据流"

28.7.3 Hybrid 模式——人机协作的三种范式

范式描述典型场景
人在环(Human-in-the-loop)Agent 提议,人类审批高风险操作(医疗、法律、金融)
人在环上(Human-on-the-loop)人类监督,Agent 自驱中风险操作(运维、客服)
人在环外(Human-out-of-the-loop)Agent 完全自治低风险操作(批量数据清理、报表生成)
没有哪一种范式是"最好"的;正确的做法是按风险分级,不同任务用不同范式——这与 ch27 §27.5 PoC 6 阶梯的逻辑一致。
判定的核心不只是风险等级,更是"可逆性"——可逆操作可以 HOOL,不可逆操作必须 HITL;读者在落地时应建立"风险 × 可逆性"二维矩阵而非单维判断。

28.8.1 三大监管框架对比

框架主体性质主要特点
EU AI Act欧盟强制法律(已通过)按风险分级(高风险禁用 / 有限风险透明 / 最小风险自律)

28.8.2 Agent 特有的伦理议题

议题描述当前主流应对
责任归属Agent 决策出错,谁负责沿用"运营方 + 厂商"连带责任
偏见与公平Agent 复制训练数据中的偏见数据审计 + 输出监测

28.8.3 监管沙盒

监管沙盒(Regulatory Sandbox)是各国应对 AI 创新的常见做法:在受控环境下允许 Agent 试运行,监管机构观察后再立法。这与 ch22 §22.7 评测沙盒是平行的两件事——一个是技术沙盒,一个是法律沙盒。

28.9 给读者的 5 条实践建议

28.9.1 选型

  1. 不要追新框架:7 大框架已经覆盖 90% 场景;选一个稳定的学透;
  2. 模型优先于框架:同一框架下,模型升级带来的收益往往大于框架切换;
  3. 可观测性是 1,其他是 0:没有可观测性,Agent 上线就是裸奔。

28.9.2 技术债

  1. 每次升级留好回滚:Agent 不是模型,升级失败可能是数据或工具的副作用;
  2. 提示词版本化:用 Git 管理 prompt,避免"这个 prompt 谁改的";
  3. 评估集是核心资产:评估集的质量决定 Agent 的质量。

28.9.3 组织债

  1. 从最贵的人工流程开始:ROI 容易量化,推进路径短;
  2. 设立 Agent CoE(Center of Excellence):统一治理、统一工具、统一评估;
  3. 法务 / 安全 / 采购从第一天进场:不要"再补一下"。

28.9.4 伦理债

  1. 决策日志是底线:Agent 做出的每个决策都需要可追溯;
  2. 高风险操作必加人在环:不可逆操作必须经过人审批;
  3. 偏见与公平定期审计:每季度评估一次,持续跟踪。

28.11 小结、速查与展望

28.11.1 8 条核心观点

  1. LLM 是大脑,Agent 是具身化,AGI 是目标——三者递进而非替代;
  2. Agent 是 AGI 现阶段最现实的路径,因为它是 LLM 与世界的接口;
  3. 短期(2026-2028)的瓶颈在组织,不在技术——ch27 三道墙仍适用;
  4. 中期(2028-2030)的突破在自进化与长时记忆——评测与安全需要同步;
  5. 长期(2030+)的开放问题是 AGI 是否可达与价值对齐——不预测具体年份;
  6. 人机分工的关键是按风险分级——高风险人在环,低风险 Agent 自治;
  7. 监管会越来越严,但技术不会停下来——监管沙盒是缓冲;
  8. 个人学习的关键是从跑通到生产化——本书 28 章的顺序就是路径。

代码 28.1 — Agent 路径路由器(LLM / Agent / Multi-Agent / 暂不可行)

# agent_pathway_router: 根据任务特征,推荐 AI 系统的最低可行形态

输入:任务描述(关键词),输出:四档之一


from typing import Literal



Route = Literal["llm_direct", "single_agent", "multi_agent", "not_feasible"]



关键词与门槛(经验值,可按业务调整)


TOOL_HINTS = {"搜索", "数据库", "邮件", "日历", "下单", "退款", "审批", "工单", "执行", "点击", "画成图", "写文件", "改库", "查询"}


MULTI_HINTS = {"协调", "分发", "审批流", "多方", "竞争", "辩论", "投票", "角色", "团队", "三个 Agent"}


NOT_FEASIBLE = {"高风险手术", "法律责任归属", "未成年人监护", "未成年人做监护", "未成年人做", "监护决策"}



def route_task(task: str) -> Route:


    """给定任务描述,返回最低可行形态。"""


    t = task.strip()


    if not t:


        return "not_feasible"


    if any(k in t for k in NOT_FEASIBLE):


        return "not_feasible"


    if any(k in t for k in MULTI_HINTS):


        return "multi_agent"


    if any(k in t for k in TOOL_HINTS):


        return "single_agent"


    return "llm_direct"



自检

    ("帮我写一首关于秋天的诗", "llm_direct"),


    ("让 AI 给未成年人做监护决策", "not_feasible"),


]

print(f"agent_pathway_router 自检: {ok}/{len(samples)} 通过")

代码 28.2 — Agent 工业化成熟度评分器(三维护城河)

# maturity_score: 评估一个 Agent 项目的工业化成熟度

三维:技术 / 组织 / 合规,每维 0-10,加权平均得总分


DIMENSIONS = {


    "技术": {


        "评估集": 2.0, "可观测性": 2.0, "安全": 1.5,


        "成本": 1.5, "版本管理": 1.0, "回滚能力": 1.0, "性能": 1.0,


    },


    "组织": {


        "明确 Owner": 2.0, "CoE 或 PM": 1.5, "Skills 治理": 1.5,


        "文档与培训": 1.0, "用户反馈回路": 1.0, "事故响应": 1.0, "沟通机制": 1.0,


    },


    "合规": {


        "数据分级": 2.0, "权限矩阵": 1.5, "审计日志": 1.5,


        "BAA 与合同": 1.0, "偏见监测": 1.0, "解释能力": 1.0, "撤销机制": 1.0,


    },


}



def maturity_score(scores: dict[str, dict[str, float]]) -> dict:


    """scores[维度][指标] = 0-10,返回各维得分与总分。"""


    result = {}


    total = 0.0


    for dim, weights in DIMENSIONS.items():


        s = scores.get(dim, {})


        dim_score = sum(s.get(k, 0) * w for k, w in weights.items()) / sum(weights.values())


        result[dim] = round(dim_score, 1)


        total += dim_score


    result["总分"] = round(total / len(DIMENSIONS), 1)


    if result["总分"] >= 8: result["等级"] = "生产级"


    elif result["总分"] >= 6: result["等级"] = "可试点"


    elif result["总分"] >= 4: result["等级"] = "PoC 阶段"


    else: result["等级"] = "探索阶段"


    return result

代码 28.3 — 人机分工建议器(按风险等级)

# human_ai_division: 对一个任务,输出人/机协作建议

风险等级:低 / 中 / 高;决策方与执行方


RISK_KEYWORDS = {


    "高": {"医疗", "手术", "法律", "诉讼", "罚款", "解约", "未成年人", "心理"},


    "中": {"运维", "客服", "审批", "采购", "财务", "HR", "IT", "订单", "退款", "修改用户", "改库", "写入"},


    "低": {"数据清理", "报表", "邮件", "文档", "搜索", "统计", "读取", "画图", "生成"},


}



def human_ai_division(task: str) -> dict:


    """按任务中的风险关键词,输出人机协作范式。"""


    t = task.strip()


    risk = "低"


    for k in ("高", "中"):


        if any(word in t for word in RISK_KEYWORDS[k]):


            risk = k


            break


    table = {


        "高": {"范式": "人在环(HITL)", "决策方": "人", "执行方": "Agent(提议)+人(审批)"},


        "中": {"范式": "人在环上(HOTL)", "决策方": "Agent", "执行方": "Agent(自驱)+人(监督)"},


        "低": {"范式": "人在环外(HOOL)", "决策方": "Agent", "执行方": "Agent(完全自治)"},


    }


    return {"任务": t, "风险等级": risk, **table[risk]}



自检

    print(human_ai_division(t))

def horizon(milestone: str) -> str:


    m = milestone.strip()


    for tag in ("短期", "中期", "长期"):


        if any(k in m for k in HORIZON_KEYWORDS[tag]):


            return tag


    return "未定"
