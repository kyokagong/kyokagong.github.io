21.1 引子:从 ch20 Browser-Use 到 ch21 Computer Use

21.1.1 一句话定义

Computer Use(直译"计算机使用")是一种让 LLM 直接驱动键鼠、看见屏幕像素、操作任意 GUI(桌面应用、移动 App、ERP、SaaS 后台、CAD、IDE、游戏…)的 Agent 范式。它把"对话"扩展为"动作",把"文本输出"扩展为"屏幕输入"——LLM 成为了一双眼睛加一双手的人类代理。

21.1.2 为什么要写 ch21?ch20 不够吗?

ch20(昨日写的 Browser-Use)是 Computer Use 的 Web 域特例——只能操作浏览器内的 HTML,而现实工作中 80% 的界面是桌面软件、移动 App、企业 ERP、SaaS 后台(它们没有 DOM,只有像素)。这正是 ch21 必须存在的原因。

举 3 个真实痛点:

  • 医院 HIS 系统:护士要查 5 个字段填写到 Excel,而 HIS 是 C++ Win32 客户端,根本没有 DOM
  • SAP GUI:财务对账需要登录 → 输 12 位凭证号 → 选 3 个下拉框 → 点保存,纯桌面操作
  • AutoCAD 画图:设计师要自动插入 200 个标准件,AutoCAD 没 DOM,但有 200 万行 Win32 API

ch21 解决的正是这类纯像素级 GUI 控制问题。

21.2 GUI Agent 范式:看 → 思考 → 行动 三段式

21.2.1 人类操作 GUI 的 4 步心路

当人类看到一个 Windows 弹窗,大脑执行:


眼睛看屏幕 → 注意力集中到按钮 → 大脑判断"这是 OK" → 手指鼠标点
   (感知)        (注意力/对焦)         (推理)            (行动)

GUI Agent 复刻这 4 步:

阶段人类Agent工具
1. 感知眼睛看屏幕`screenshot()`Pillow / mss / playwright
2. 注意力焦点定位`find(target)`OCR / 模板匹配 / VLM grounding
3. 推理大脑判断LLM CoTClaude Sonnet 4.5 / GPT-4o / Qwen3-VL
4. 行动手操作键鼠`click(x,y)` / `type(s)` / `key(k)`pyautogui / xdotool / pywinauto

21.2.2 与 ch05 ReAct 的 5 区别

ch05 写过 ReAct 范式(Reasoning + Acting),它适用于文本环境(搜索 / 数据库 / API);ch21 的 observe-think-act 把"环境观察"从文本信号升级为像素信号,带来 5 个根本区别:

维度ch05 ReAct(文本环境)ch21 observe-think-act(像素环境)
环境状态`result = search(q)` 字符串1920×1080 RGB array(6 MB)
观察信号工具返回值截图像素 + 可选文本
决策信号LLM 文本LLM 多模态输入(图像+文本)
鲁棒性高(文本决定论)低(像素飘移、对焦失败)

21.3 感知层:屏幕截图的 6 维度

21.3.1 DOM 抽象 vs Pixels(为什么 Browser-Use 失灵)

ch20 的核心优势是DOM 抽象:浏览器把 HTML 解析成一棵有标签的树,Agent 通过 id="ok-button" 直接锁定元素。而 90% 的桌面应用没有 DOM,只有无差别的 RGB 像素:

  • Win32 应用(记事本、Outlook、AutoCAD、SAP GUI)→ Win32 句柄
  • macOS 应用(Keynote、Numbers)→ Accessibility hierarchy
  • X11 应用(Linux 桌面)→ AT-SPI 节点
  • Android 应用 → uiautomator dump 出来的 XML
  • iOS 应用 → XCUITest accessibility

所以 ch21 必须从像素开始。

21.3.2 6 个感知维度

维度工具输出优点缺点
1. 像素 RGB`mss.grab()`numpy[H, W, 3]通用、无依赖信息密度低
2. 文本`pytesseract.image_to_string`字符串找文字准截图小、易漏读
3. 控件(accessibility tree)`pywinauto` / `atomac`元素列表精确、可点击仅支持部分框架
4. 焦点`pywin32.GetForegroundWindow`当前窗口句柄找焦点快跨平台不一致
5鼠标位置(读取)`pyautogui.position()`(x, y)易DPI 缩放失准
6屏幕变化`numpy diff()`变化区域找新弹窗阈值难调
注:第 5 项是"读取"当前鼠标位置(用于状态校验),第 1-4 项是"控制"(改变屏幕状态)。两类必须严格区分,GUI Agent 必须在"读取 → 决策 → 控制"三类间可追溯。

21.3.3 Accessibility Tree vs Pixels 的 4 关键区别

维度Accessibility Tree(可访问性树)Pixels(像素)
数据量100-1000 节点2 MB / 帧
元素定位`{"role": "button", "name": "OK", "x": 124}`需要 OCR + 坐标推理
可靠性高(结构稳定)中(DPI/动效影响)
跨应用一致一般(各 OS 协议不同)通用

经验:优先用 Accessibility Tree(可访问性树),失败再回退 Pixels(chrome devtools 的 ARIA tree、SAP GUI Scripting、Win32 UIA、macOS AXUIElement 都是"白送的 DOM")。

21.3.3a 像素工程的 3 种主流方案

方案工具性能成本适用
**全屏 sreenshot 每步一次**`pyautogui.screenshot()`简单但慢(每步 200 ms)高(网络传输)调试期
**变化区域检测**`numpy.diff(前帧, 当前帧) > threshold`快(只传 diff)低生产期
**ROI 区域**`pyautogui.screenshot(region=(x, y, w, h))`快低只关心某区域

21.3.4 多模态决策与单模态决策的本质差异

GUI Agent 与 ch20 Browser-Use 的核心区别不是工具差异,而是决策空间。DOM 决策在 HTML 节点结构里,LLM 输出 {"selector": "#ok"} 字符串即可;像素决策在 RGB 三维数组里,LLM 必须先把"看到什么"映射到"行动什么",中间多一道视觉推理,失败率从 1-5% 提升到 5-15%。

21.3.5 屏幕坐标系的 4 个陷阱(写入工程纪要)

#陷阱触发解决
1DPI 缩放不匹配Windows 125% 缩放时模型训练用 1600×1200,实测用 125% 缩放后的实际像素`pyautogui.size()` + `Image.resize()` 对齐
2多屏坐标错乱Agent 在 screen 2 控制,LLM 决策给的是 screen 1 坐标加 `(screen_id, x, y)` 三元组
3Retina vs 非 RetinamacOS Retina 截图分辨率大于实际像素用 `image.size[0] // 2` 校准
4Active vs Hidden Window模型识别到被最小化的窗口,实际点击无响应加 `isWindowActive()` 校验

21.6 30 行最小 GUI Agent Hello World(pyautogui + 截图)

21.6.1 完整代码(可运行,Mock 模式)


"""
ch21.6.1 - 30 行最小 GUI Agent Hello World
依赖: pip install pillow pyautogui
       (本演示用 mock 截图,不需真实显示器)
"""
import time, base64, io
from PIL import Image
import pyautogui

def take_screenshot():
    """拍一张屏幕(演示用 mock 80×60 像素图)"""
    img = Image.new("RGB", (80, 60), "white")
    # 画一个"OK 按钮"在 (40, 30)
    for x in range(35, 45):
        for y in range(27, 33):
            img.putpixel((x, y), (200, 200, 200))
    return img

def encode_b64(img):
    buf = io.BytesIO()
    img.save(buf, format="PNG")
    return base64.b64encode(buf.getvalue()).decode()

def mock_llm(prompt, screenshot_b64):
    """模拟 LLM 决策:看到 OK 按钮就点"""
    if "OK" in prompt or "按钮" in prompt:
        return {"action": "click", "x": 40, "y": 30}
    return {"action": "noop"}

# ---- 30 行主循环 ----
img = take_screenshot()                       # 1. 感知
b64 = encode_b64(img)                         # 2. 编码
decision = mock_llm("点击 OK 按钮", b64)        # 3. 决策
print(f"[STEP 1] 决策: {decision}")

if decision["action"] == "click":
    # pyautogui.click(decision["x"], decision["y"])  # 真实环境
    print(f"[STEP 2] (Mock) 在 ({decision['x']}, {decision['y']}) 已点击")
    img2 = take_screenshot()
    if img2.getpixel((40, 30)) == (200, 200, 200):
        print("[STEP 3] ✅ OK 按钮状态确认")
    else:
        print("[STEP 3] ❌ 没点中,重试")
        time.sleep(0.1)
print("✅ GUI Agent 完成一次 observe-think-act 循环")

运行输出:

[STEP 2] (Mock) 在 (40, 30) 已点击
[STEP 3] ✅ OK 按钮状态确认

21.6.2 把 mock 替换为真实 Claude Computer Use(扁平结构)


# 把 mock_llm 换成 Anthropic Claude Computer Use
# 真实 API 用 flat 结构 + tools 枚举类型(非内嵌 input_schema)
import anthropic
client = anthropic.Anthropic()

def real_llm(task, screenshot_b64):
    resp = client.messages.create(
        model="claude-sonnet-4.5",
        max_tokens=1024,
        tools=[{
            "type": "computer_20241022",  # Computer Use 工具类型(2024-10 版)
            "name": "computer",
            "display_width_px": 1600,
            "display_height_px": 1200
        }],
        messages=[{
            "role": "user",
            "content": [
                {"type": "image",
                 "source": {"type": "base64", "media_type": "image/png", "data": screenshot_b64}},
                {"type": "text", "text": task}
            ]
        }]
    )
    # resp.stop_reason == "tool_use" 时,从 content 块取 input
    for block in resp.content:
        if block.type == "tool_use":
            return block.input  # 形如 {"action": "left_click", "coordinate": [124, 567]}
    return {"action": "done"}
注:Anthropic Computer Use 的工具定义是扁平 type: "computer_20241022" + display 字段,返回的 block.input 是 {action, coordinate?, text?, ...}。截图必须是 image/png 且 base64 后 < 5 MB,否则报 413。

现象根因修复

import json, hashlib, base64, os
from datetime import datetime

class GUIAgentTrace:
    def __init__(self, save_dir="./gui_trace"):
        self.dir = save_dir
        os.makedirs(save_dir, exist_ok=True)
        self.records = []
    def record(self, step, screenshot_b64, decision, env_state_hash):
        ts = datetime.now().isoformat()
        fname = f"{self.dir}/{step:04d}-{ts}.png"
        with open(fname, "wb") as f: f.write(base64.b64decode(screenshot_b64))
        self.records.append({
            "step": step, "ts": ts, "decision": decision,
            "png": fname, "env_state_hash": env_state_hash
        })
    def save(self):
        with open(f"{self.dir}/trace.json", "w") as f:
            json.dump(self.records, f, indent=2, ensure_ascii=False)

21.7.3 撤销栈代码(15 行)


"""
ch21.7.3 - 撤销栈演示(配合 21.7 #4)
"""
import shutil, os, time
class UndoStack:
    def __init__(self, workdir):
        self.workdir = workdir
        self.stack = []
    def snapshot(self, name):
        path = f"{self.workdir}/.snapshots/{name}-{int(time.time())}"
        shutil.copytree(self.workdir, path, ignore=lambda *a: {".snapshots"})
        self.stack.append(path)
    def undo(self):
        if not self.stack: return False
        last = self.stack.pop()
        for f in os.listdir(self.workdir):
            if not f.startswith(".snapshots"):
                os.remove(f"{self.workdir}/{f}")
        shutil.copytree(last, self.workdir, dirs_exist_ok=True)
        return True

# u.undo()                 # 回滚

21.9.2 死循环防护代码(15 行)


"""
ch21.9.2 - 防止 GUI Agent 进入死循环的关键阈值
"""
class CircuitBreaker:
    def __init__(self, max_steps=30, no_change_max=5):
        self.max_steps = max_steps
        self.no_change_max = no_change_max
        self.steps = 0
        self.last_state = None
        self.no_change_count = 0
    def step(self, current_state):
        self.steps += 1
        if self.steps > self.max_steps:
            raise RuntimeError(f"超过 {self.max_steps} 步,自动停止")
        if current_state == self.last_state:
            self.no_change_count += 1
            if self.no_change_count > self.no_change_max:
                raise RuntimeError(f"连续 {self.no_change_max} 步画面未变化,可能死循环")
        else:
            self.no_change_count = 0
            self.last_state = current_state

# 用法:
# cb = CircuitBreaker(max_steps=30, no_change_max=5)
# while True: cb.step(screenshot_hash())

21.11.5 ch21 与第一部分(基础与生态)的呼应

回看 ch01 提到的"Agent 的 5 大特征"(自主性、反应性、主动性、社会性、进化性),ch21 的 Computer Use 是这 5 个特征的最完整展示:

ch01 特征ch21 的实现
自主性在无人介入的 sandbox 内完成整段 GUI 任务
反应性看到弹窗即时调整下一步行动
主动性自己定位 OK 按钮并主动点击
社会性与桌面其他进程(IDE / 浏览器 / 文件管理器)交互
进化性通过 trace replay 累积改进 CoT 提示词

读者可以在读完 21.2.3 三段式后,回头思考"这是不是 LLM 第一次完整实现了 ch01 所说的 Agent?"—— 答案是部分实现了,因为 Computer Use 还不能从经验中主动学习,而是每次任务从零启动(自我改进要等到 ch25)。
