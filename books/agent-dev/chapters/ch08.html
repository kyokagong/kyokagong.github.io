记忆系统

短期 / 长期 / 向量 / 知识图谱

8.1 引子：为什么 Agent 需要"记忆"

LLM 本身是无状态的——每一次 chat.completions.create() 调用，对模型来说都是"第一次见到这段对话"。你以为它在"回忆"上一轮你说的话，其实只是你把历史消息又塞了一遍进 messages 数组。这就是为什么 Agent 必须有"记忆"系统——它要自己负责"我之前说过什么 / 做过什么 / 学到什么"。

8.1.1 3 个真实痛点

痛点现象根因
多轮对话上下文丢失用户说"把它改成蓝色"，Agent 问"改成什么蓝色？"短期记忆（context）被截断或没保存
工具调用结果取不回用户 5 分钟前查过北京天气，现在再问，Agent 又查一遍工具结果没写进长期记忆，只在 context 短暂存在
用户偏好每次重问用户每次都说"我不吃辣"，Agent 每次都问"辣到什么程度？"用户偏好没沉淀，Agent 永远"第一次见"用户
这 3 个痛点的共同解药：记忆系统。短期记忆解决"上下文丢失"——把历史消息保留在 context 里（或摘要后保留）。长期记忆解决"工具结果取不回 + 用户偏好"——把结果和偏好写进 DB / 向量库，下次直接命中。

8.1.2 人脑记忆 vs Agent 记忆

人脑的记忆有 3 层：感官记忆（几百毫秒）、短期记忆（~7 个 chunk / 30 秒）、长期记忆（几天～一辈子）。Agent 的记忆也分层，但边界是工程定义的，不是生物学的。

人脑层时长 / 容量Agent 对应层工程实现速度
感官记忆< 1 秒当前输入流（用户本轮 prompt + tool result）messages 数组最新一条ns 级
短期记忆~30 秒 / 7 chunkcontext windowLLM 的 input tokensms 级（推理时）
长期记忆几天～一辈子外部 DB / 向量库 / 知识图谱SQLite / Chroma / Neo4jμs-ms 级（检索时）
长期情节记忆个人经历向量记忆（embedding）Chroma / FAISS / Pineconems 级
长期语义记忆概念 / 事实知识图谱（KG）Neo4j / Memgraphms 级（多跳查询）
关键洞察：人脑的"长期记忆"在 Agent 这里被拆成了 3 种工程实现——DB（结构化）、向量库（相似度）、图谱（关系）。这 3 种各有优势，生产级 Agent 几乎都同时用 3 种——这就是 8.6 的"混合架构"。

8.2 短期记忆（Short-term Memory）

本质：context window 内的 messages 数组。LLM 看到的"上文"就是短期记忆——它的"工作记忆"。

8.2.2 短期记忆的 3 大局限

  1. 价格随长度线性增长——128K context 的 GPT-4o 一次推理 ≈ $0.32（输入），用满 200K Claude 3.7 ≈ $0.60。多轮对话每轮都把全部历史塞回去，成本爆炸。
  2. 注意力衰减（Lost in the Middle）——模型对中段信息的关注度显著低于头尾。Liu et al. 2023 实验：把关键信息放中间，LLM 准确率掉 30+ pp。
  3. 超过 window 强制截断——超出 128K 的消息直接报错或被静默截断（取决于 SDK）。你不能依赖"足够大的 context"——必须主动管理。

8.2.3 3 种工程策略

策略原理优点缺点适用场景
滑动窗口（Sliding Window）只保留最近 N 条消息简单、可控丢失远期上下文多轮闲聊 / 短任务
摘要压缩（Summary Compression）每 K 条消息触发一次摘要，把 N 条压成 1 条保留远期语义摘要可能丢细节长会话（客服 / 辅导）
关键消息保留（Key Message Pinning）手动或自动标记 system 消息 / 关键决策，永远保留关键信息不丢需要"重要 vs 不重要"的判断逻辑任务型 Agent（必须记住用户偏好）
生产最佳实践：滑动窗口 + 摘要压缩 + 关键消息保留 三合一——默认滑动（最近 10 条），每 20 条触发一次摘要，关键的 system / 决策消息永远保留在头部。

8.2.4 Python 实战：滑动窗口 + 摘要压缩

"""
8.2.4 短期记忆管理：滑动窗口 + 摘要压缩 + 关键消息保留
全部用 mock LLM（不调真实 API），结构与真实代码一致
"""

import datetime
from collections import deque

class ShortTermMemory:
    """短期记忆 = context window 内的 messages 数组管理"""

    def __init__(self, window_size=10, summary_trigger=20):
        self.window_size = window_size          # 滑动窗口：保留最近 N 条
        self.summary_trigger = summary_trigger   # 每 N 条触发一次摘要
        self.messages = []                       # 完整历史（持久化用）
        self.summary = ""                        # 历史摘要
        self.key_messages = []                   # 关键消息（永远保留）

    def add(self, role: str, content: str, pinned: bool = False):
        """加一条消息；pinned=True 表示关键消息"""
        msg = {
            "role": role,
            "content": content,
            "timestamp": datetime.datetime.now().isoformat(),
            "pinned": pinned,
        }
        self.messages.append(msg)
        if pinned:
            self.key_messages.append(msg)
        # 触发摘要：每 summary_trigger 条
        if len(self.messages) % self.summary_trigger == 0:
            self._compress()
        return self

    def _compress(self):
        """mock 摘要：把中段消息拼成一段总结"""
        if len(self.messages) <= self.window_size:
            return
        # 滑动窗口外 + 已摘要过的，合成 summary
        to_summarize = self.messages[:-self.window_size]
        self.summary = f"[摘要: {len(to_summarize)} 条历史消息] " + \
                       f"包含 {sum(1 for m in to_summarize if m['role']=='user')} 条用户提问"
        # 真实场景这里调 LLM 做摘要；mock 简化

    def get_context(self) -> list:
        """组装给 LLM 的 messages：关键消息 + 摘要 + 滑动窗口"""
        context = list(self.key_messages)  # 关键消息永远在最前
        if self.summary:
            context.append({
                "role": "system",
                "content": f"历史对话摘要: {self.summary}",
                "pinned": False,
            })
        # 滑动窗口：最近 N 条
        context.extend(self.messages[-self.window_size:])
        return context


# ---- 演示 ----
stm = ShortTermMemory(window_size=4, summary_trigger=5)
stm.add("system", "你是一个 helpful 助手", pinned=True)
stm.add("user", "你好")
stm.add("assistant", "你好！有什么可以帮你的？")
stm.add("user", "北京今天天气怎么样？")
stm.add("assistant", "我去查一下。")
stm.add("user", "顺便问一下上海呢？")     # 第 5 条，触发摘要
stm.add("assistant", "好的，正在查。")
stm.add("user", "广州天气？")
stm.add("assistant", "马上。")
stm.add("user", "深圳？")              # 第 9 条，再触发一次摘要
stm.add("assistant", "稍等。")

print(f"总消息数: {len(stm.messages)}")
print(f"关键消息: {len(stm.key_messages)} 条")

8.3 长期记忆（Long-term Memory）

本质：跨 session 持久化到外部存储。短期记忆的最大缺点是"窗口有限 + 会话结束就清空"——长期记忆解决这个。

形式容量上限检索能力适用场景典型代表

PostgreSQLTB 级复杂 SQL / 全文检索中大型企业生产级聊天系统

选型决策树：
  • < 1MB + 单用户 → JSON 文件
  • < 1GB + 个人 → SQLite
  • > 1GB + 多人 → PostgreSQL
  • 热数据 / 要快 → Redis（缓存层）
  • 语义搜索 → 向量库（见 8.4）

8.4 向量记忆（Vector Memory）

本质：embedding + 相似度检索。把文本变成高维向量（1536 维 for OpenAI），用余弦相似度找"最像的 N 个"。

8.4.1 Embedding 模型选型

8.4.2 5 步流程

  1. 文本切分（chunking）——长文档切成 200-1000 token 的小块，重叠 10-20%。工具：langchain.text_splitter.RecursiveCharacterTextSplitter
  2. 调 embed API——对每个 chunk 调 embedding 模型，得 1536 维向量
  3. 写入向量库——chunk 原文 + embedding 向量 + metadata（source / timestamp / author）
  4. 查询时 embed query——把用户问题也转成向量
  5. 相似度 top-K——在向量库中找 top-K（K=3-10）最相似的 chunk，拼成 context 送 LLM

选型建议：
  • 原型 / < 1M 向量 → Chroma（5 行代码起步）
  • 大规模本地 → FAISS（Meta 出品，最快）
  • 企业级 / 要国产化 → Milvus（国产 + 中文社区）
  • 不想运维 / 快速上线 → Pinecone（最贵但最省心）

8.4.4 Python 实战：Chroma 风格的 mock 向量库

"""
8.4.4 向量记忆：Chroma 风格 mock 实现
真实 Chroma 用 `pip install chromadb` 后 import；mock 演示检索逻辑
"""

import math
from typing import List

class MockChroma:
    """Mock 向量库：用纯 Python 字典 + 余弦相似度，模拟 Chroma 接口"""

    def __init__(self):
        self.docs = {}        # id -> {"text": ..., "embedding": [...], "metadata": {...}}

    def add(self, doc_id: str, text: str, embedding: List[float], metadata: dict = None):
        self.docs[doc_id] = {
            "text": text,
            "embedding": embedding,
            "metadata": metadata or {},
        }

    def query(self, query_embedding: List[float], top_k: int = 3) -> List[dict]:
        """余弦相似度 top-K"""
        scores = []
        for doc_id, doc in self.docs.items():
            sim = self._cosine(query_embedding, doc["embedding"])
            scores.append((sim, doc_id, doc))
        scores.sort(reverse=True, key=lambda x: x[0])
        return [
            {"id": did, "text": d["text"], "metadata": d["metadata"], "score": s}
            for s, did, d in scores[:top_k]
        ]

    @staticmethod
    def _cosine(a: List[float], b: List[float]) -> float:
        """余弦相似度"""
        dot = sum(x * y for x, y in zip(a, b))
        norm_a = math.sqrt(sum(x * x for x in a))
        norm_b = math.sqrt(sum(x * x for x in b))
        return dot / (norm_a * norm_b + 1e-9)


def mock_embed(text: str) -> List[float]:
    """Mock embedding：按文本字符数生成 8 维伪向量"""
    # 真实场景调 OpenAI / BGE API；mock 用 hash 模拟
    return [math.sin(hash(c) % 100) for c in text[:8].ljust(8, ' ')]


# ---- 演示：把 ch07 工具调用结果写进向量库，下次查询 ----
chroma = MockChroma()
chroma.add("w1", "北京今天多云，18°C",
           mock_embed("北京今天多云，18°C"),
           {"tool": "get_weather", "city": "北京", "ts": "2026-06-17"})
chroma.add("w2", "上海今天晴，22°C",
           mock_embed("上海今天晴，22°C"),
           {"tool": "get_weather", "city": "上海", "ts": "2026-06-17"})
chroma.add("w3", "广州今天雷阵雨，28°C",
           mock_embed("广州今天雷阵雨，28°C"),
           {"tool": "get_weather", "city": "广州", "ts": "2026-06-17"})

# 用户问："北京什么天气？"
query = "北京什么天气？"
results = chroma.query(mock_embed(query), top_k=2)
print(f"查询: {query}\n")
print(f"Top-{len(results)} 命中:")
for r in results:
    print(f"  [{r['score']:.3f}] {r['text']}  (city={r['metadata'].get('city')})")

预期输出： 

查询: 北京什么天气？

Top-2 命中:
  [0.998] 北京今天多云，18°C  (city=北京)
  [0.516] 上海今天晴，22°C  (city=上海)

关键观察：向量检索不需要"包含'北京'"的字面匹配——它靠"语义相似"找到正确结果。即使你写"首都天气"也能命中"北京"。这就是 8.4 的工程价值。

注意：本示例的 mock_embed 是简化实现（用 hash() 生成伪向量，受 Python PYTHONHASHSEED 影响），真实场景调 BGE / OpenAI API 后相似度排序稳定。本示例重点演示接口契约，不保证 mock 排序绝对稳定。

8.5 图谱记忆（Graph Memory）

本质：实体-关系-实体三元组 (head, relation, tail)，存的是"谁和谁是什么关系"。

8.5.1 向量 vs 图谱：互补关系

维度向量记忆图谱记忆
擅长相似度（"差不多的东西"）精确关系（"是...的父亲 / 属于... / 在...工作"）
查询方式余弦相似度 top-K多跳遍历（Cypher / SPARQL）
适合数据文档 / 对话 / 描述性文本人物关系 / 组织架构 / 知识依赖
典型问题"和'北京'相关的内容""北京是哪个国家的首都？"
不擅长精确的"等于"查询"意思差不多的"模糊查询
生产最佳实践：向量 + 图谱一起用。先用向量检索找相关文档 / 上下文，再用图谱查询精确关系补全细节。OpenAI 的 *"GraphRAG"*（2024）就是这个思路。

8.5.2 Neo4j / Memgraph / JSON 三元组 3 方案对比

方案部署查询语言规模适用

8.5.3 Python 实战：JSON 三元组简易知识图谱

"""
8.5.3 图谱记忆：JSON 三元组 + 多跳遍历
"""

# 三元组：(head, relation, tail) —— 真实场景存 Neo4j
triples = [
    ("北京", "是...的首都", "中国"),
    ("上海", "是...的经济中心", "中国"),
    ("北京", "举办过", "2008 奥运会"),
    ("北京", "举办过", "2022 冬奥会"),
    ("张三", "工作于", "北京"),
    ("张三", "认识", "李四"),
    ("李四", "工作于", "上海"),
]

class TinyKG:
    def __init__(self, triples):
        self.triples = triples
        # 建索引：head -> [(relation, tail)]
        self.index = {}
        for h, r, t in triples:
            self.index.setdefault(h, []).append((r, t))

    def query(self, head: str, relation: str = None, max_hops: int = 1) -> list:
        """简单多跳：找出 head 的所有相关三元组，可按 relation 过滤"""
        results = []
        visited = set()
        queue = [(head, 0)]
        while queue:
            node, depth = queue.pop(0)
            if depth > max_hops or node in visited:
                continue
            visited.add(node)
            for r, t in self.index.get(node, []):
                if relation is None or r == relation:
                    results.append((node, r, t))
                if depth + 1 <= max_hops:
                    queue.append((t, depth + 1))
        return results

    def multi_hop(self, start: str, target: str, max_hops: int = 3) -> list:
        """BFS 找从 start 到 target 的最短路径"""
        from collections import deque
        # visited: node -> (prev_node, relation)；起点 None 表示无前驱
        visited = {start: None}
        q = deque([start])
        while q:
            node = q.popleft()
            if node == target:
                # 重建路径：从 target 回溯到 start
                path = []
                cur = node
                while visited[cur] is not None:  # 起点 visited[start]=None
                    prev, r = visited[cur]
                    path.append((prev, r, cur))
                    cur = prev
                return list(reversed(path))
            for r, t in self.index.get(node, []):
                if t not in visited:
                    visited[t] = (node, r)
                    q.append(t)
        return []


kg = TinyKG(triples)

print("=== 查询 1：'北京' 的所有关系 ===")
for h, r, t in kg.query("北京"):
    print(f"  ({h}) --{r}--> ({t})")

print("\n=== 查询 2：张三 → 上海 多跳路径 ===")

for h, r, t in path:
    print(f"  ({h}) --{r}--> ({t})")

8.6.3 Python 实战：4 种记忆混合检索

"""
8.6.3 4 种记忆混合检索 demo
（独立可运行：内嵌 MockChroma / TinyKG / mock_embed）
"""

import math
from collections import deque

def mock_embed(text: str):
    """Mock embedding：按文本字符数生成 8 维伪向量"""
    return [math.sin(hash(c) % 100) for c in text[:8].ljust(8, ' ')]

class MockChromaInline:
    def __init__(self):
        self.docs = {}
    def add(self, doc_id, text, embedding, metadata=None):
        self.docs[doc_id] = {"text": text, "embedding": embedding, "metadata": metadata or {}}
    def query(self, query_embedding, top_k=3):
        def cosine(a, b):
            dot = sum(x*y for x, y in zip(a, b))
            na = math.sqrt(sum(x*x for x in a)); nb = math.sqrt(sum(x*x for x in b))
            return dot / (na * nb + 1e-9)
        scores = sorted(
            [(cosine(query_embedding, d["embedding"]), did, d) for did, d in self.docs.items()],
            reverse=True)
        return [{"id": did, "text": d["text"], "metadata": d["metadata"], "score": s}
                for s, did, d in scores[:top_k]]

class TinyKGInline:
    def __init__(self, triples):
        self.triples = triples
        self.index = {}
        for h, r, t in triples:
            self.index.setdefault(h, []).append((r, t))
    def query(self, head, relation=None, max_hops=1):
        results = []; visited = set(); queue = deque([(head, 0)])
        while queue:
            node, depth = queue.popleft()
            if depth > max_hops or node in visited: continue
            visited.add(node)
            for r, t in self.index.get(node, []):
                if relation is None or r == relation:
                    results.append((node, r, t))
                if depth + 1 <= max_hops: queue.append((t, depth + 1))
        return results

class HybridMemory:
    def __init__(self):
        self.short_term = []                  # 当前 context
        self.db = {}                          # 长期结构化（用户偏好）
        # 复用 8.4.4 的 MockChroma 与 mock_embed —— 此处完整内嵌以保证独立可运行
        self.vector = MockChromaInline()      # 长期向量
        self.graph = TinyKGInline([])         # 长期图谱

    def remember_preference(self, user_id: str, key: str, value: str):
        """长期 DB：用户偏好"""
        self.db.setdefault(user_id, {})[key] = value

    def remember_tool_result(self, tool: str, result: str, metadata: dict):
        """长期向量：工具结果"""
        doc_id = f"{tool}_{metadata.get('ts', 'now')}_{hash(result) % 10000}"
        self.vector.add(doc_id, result, mock_embed(result), metadata)

    def remember_relation(self, head: str, relation: str, tail: str):
        """长期图谱：实体关系"""
        self.graph.triples.append((head, relation, tail))
        self.graph.index.setdefault(head, []).append((relation, tail))

    def retrieve(self, query: str, user_id: str = "default") -> dict:
        """混合检索：4 种记忆并行查"""
        return {
            "short_term_context": self.short_term[-5:],  # 最近 5 条
            "user_preferences": self.db.get(user_id, {}),
            "similar_tool_results": self.vector.query(mock_embed(query), top_k=2),
            "related_entities": self.graph.query(query.split()[0]) if query else [],
        }

8.7 记忆的"遗忘"机制

为什么需要遗忘：

  1. 防止 context 爆（所有记忆堆 context → 价格爆炸）
  2. 移除过期信息（"用户去年说喜欢吃辣"现在可能不喜欢了）
  3. 节省存储成本（10 年的聊天记录没必要全留）

8.7.1 3 种遗忘策略

策略原理实现难度适用
时间衰减30 天前的记忆降权（乘以 0.5），90 天前的丢弃低短期时效数据（天气、新闻）
重要性评分被引用次数多的记忆 = 不忘（"用户偏好"经常被命中）中用户偏好 / 关键决策
用户主动删除提供"删除记忆" API / UI，让用户控制低（但需要 UX）隐私敏感场景

8.7.2 GDPR / 数据合规

欧盟 GDPR（2018 生效）规定用户有"被遗忘权"——用户可以要求删除他所有的个人数据。Agent 系统的实现：

  • 每个用户的所有记忆（短期 + 长期 + 向量 + 图谱）必须能一键删除
  • 删除必须真正删除（包括向量库的 embedding）。Chroma / Pinecone / Milvus 现代版本均支持按 id 直接删除（无需重建索引），但要确认你用的版本支持；FAISS 等本地库需要重建索引。
  • 删除必须审计日志可追溯（证明"我删了"）

工程实现：每个用户记忆存 user_id 标签，删除时 DELETE WHERE user_id = ?（DB）+ collection.delete(where={"user_id": u1})（向量库）+ MATCH (n {user_id: 'u1'}) DELETE n（图谱）。

  ↓ (ch08 记忆层：同时把 tool_result 写进向量库)

8.8.3 一个完整的"ch07 + ch08" Agent 主循环

"""
8.8.3 ch07 协议 + ch08 记忆：完整 Agent 主循环（伪代码）
（独立可运行：含 mock llm_call / execute_tool / now）
"""

from datetime import datetime
def now(): return datetime.now().isoformat()

class MockMessage:
    def __init__(self, content="", tool_calls=None):
        self.content = content
        self.tool_calls = tool_calls or []
    def has_tool_calls(self): return len(self.tool_calls) > 0

ALL_TOOLS = ["get_weather", "send_reminder"]  # mock 工具清单

def llm_call(messages, tools=None):
    """Mock LLM：若消息里有 '北京'，输出 get_weather 工具调用；否则直接回复"""
    user_msg = next((m["content"] for m in reversed(messages) if m["role"]=="user"), "")
    if "天气" in user_msg and not any(m.get("role")=="tool" for m in messages):
        return MockMessage(tool_calls=[{
            "id": "call_001", "function": {"name": "get_weather", "arguments": '{"city":"北京"}'}
        }])
    return MockMessage(content=f"已为您查询：{user_msg}")

def execute_tool(name, args):
    """Mock 工具：get_weather 返回固定结果；其他返回通用"""
    if name == "get_weather":
        return {"temp": 18, "condition": "多云", "city": args.get("city")}
    return {"status": "ok", "tool": name, "args": args}

def agent_loop(user_query: str, memory) -> str:
    # 1. 从记忆里检索上下文
    retrieved = memory.retrieve(user_query)

    # 2. 拼 prompt：短期 + 长期 偏好 + 相似记忆 + 系统提示
    messages = [
        {"role": "system", "content": f"用户偏好: {retrieved['user_preferences']}"},
        *memory.short_term,                                  # 短期 context
        {"role": "user", "content": user_query},
    ]

    # 3. 调 LLM（ch07 协议层：可能输出 tool_calls）
    response = llm_call(messages, tools=ALL_TOOLS)

    # 4. 如果 LLM 决定调工具
    while response.has_tool_calls():
        for tc in response.tool_calls:
            # 4a. 调真实工具（tc 可能是 dict 或对象，统一取值）
            tc_id = tc["id"] if isinstance(tc, dict) else tc.id
            tc_name = tc["function"]["name"] if isinstance(tc, dict) else tc.function.name
            tc_args_raw = tc["function"]["arguments"] if isinstance(tc, dict) else tc.function.arguments
            import json
            tc_args = json.loads(tc_args_raw) if isinstance(tc_args_raw, str) else tc_args_raw
            result = execute_tool(tc_name, tc_args)

            # 4b. ★关键：把结果写进长期记忆（ch08）
            memory.remember_tool_result(
                tool=tc_name,
                result=str(result),
                metadata={"args": tc_args, "ts": now()},
            )

            # 4c. 回传 tool result 给 LLM（ch07 协议）
            messages.append({
                "role": "tool",
                "tool_call_id": tc_id,
                "content": str(result),
            })

        # 4d. 再调 LLM（可能再调工具 / 出最终答案）
        response = llm_call(messages, tools=ALL_TOOLS)

    return response.content


# ---- 演示（mock 跑通主循环）----
mem_stub = type("M", (), {
    "short_term": [],
    "retrieve": lambda self, q: {"user_preferences": {"language":"中文"}, "short_term_context": []},
    "remember_tool_result": lambda self, **kw: None,
})()

#坑后果修复
1把所有对话都塞进 context成本爆炸 + lost in the middle用 8.2 的滑动窗口 + 摘要压缩
2用 embedding 存"最近 10 条对话"短文本 embedding 质量差（< 50 token 区分度低）短文本用 DB 全文检索，> 100 token 才用向量

4图谱关系硬编码实体关系变化时 KG 失效用动态图谱（每次推理自动 kg.add()）
5忽略 PII / GDPR把用户身份证号永久存进向量库 → 违规写记忆前过滤 PII（regex 检测身份证 / 信用卡）
5 大坑 × 修复示例： 
# 坑 5 修复示例：PII 过滤
import re

PII_PATTERNS = [
    (r"\d{17}[\dXx]", "身份证号"),
    (r"\d{16}", "银行卡号"),
    (r"1[3-9]\d{9}", "手机号"),
    (r"[\w.-]+@[\w.-]+\.\w+", "邮箱"),
]

def filter_pii(text: str) -> str:
    for pattern, name in PII_PATTERNS:
        text = re.sub(pattern, f"[{name}已脱敏]", text)
    return text

# 使用：写入记忆前先过滤
user_input = "我的身份证号 110101199003078888，手机 13800138000"
safe_text = filter_pii(user_input)
print(f"原始: {user_input}")
print(f"脱敏: {safe_text}")

8.11 本章小结 + 概念速查 + 概念桥

8 条速记

  1. 短期记忆 = context window，128K-2M tokens，但价格线性 + lost in the middle
  2. 长期记忆 = 5 种存储（JSON/SQLite/PG/Redis/向量库），按规模选型
  3. 向量记忆 = embedding + 相似度，擅长语义检索，不擅长精确关系
  4. 图谱记忆 = 三元组 + 多跳，擅长精确关系，不擅长模糊匹配
  5. 生产 Agent = 4 种记忆混合：短期 + DB + 向量 + 图谱
  6. 遗忘是必须：时间衰减 / 重要性评分 / 用户主动删除 + GDPR 合规
  7. ch07 + ch08 互补：协议层传数据，记忆层存数据
  8. 每个框架都有自己的记忆模块：LangChain/LangGraph/AutoGen/CrewAI/OpenAI SDK 各有侧重
